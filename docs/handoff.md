# Handoff: текущее состояние проекта

Обновлено: 2026-09-02.

## Где мы

Пакет `conveyor` 1.0.0 (нигде не опубликован, потребителей нет)
переделывается в пакет `solo`: то же ядро последовательных задач с
гарантией монопольного владения состоянием, но с новым публичным API на
обычных `async`-функциях вместо генераторов. Рядом появится
`packages/flutter_solo` с `ValueListenable`-лицом.

Фаза: **дизайн согласован, план реализации написан и ждёт одобрения
владельца. Код не тронут.**

Спецификация: `docs/records/2026-09-02[1]-solo-design.md`, согласована
владельцем целиком. План: `docs/records/2026-09-02[2]-solo-plan.md` —
20 задач с TDD и коммитом на каждую, от переименования пакета до README.

План закрывает несколько мест, которые спецификация оставила реализации
(раздел «Решения, принятые в плане»). Владельцу стоит взглянуть на них до
старта: `part`-файлы в `lib/src/`; `keepWhile` проверяется и перед стартом;
`Solo.publish` откладывает вложенные публикации, потому что синхронный
broadcast-стрим бросает `Bad state` при `add` из слушателя (проверено на
Dart 3.13.0); `emit`/`run` после завершения задачи бросают `StateError`;
состояние примера `Failed` названо `Broken` из-за конфликта имён с исходом
`Failed`; старый код 1.x удаляется сразу после переименования (задача 1b),
а не живёт рядом.

Код в `packages/solo/lib/` — старая реализация `conveyor` 1.x. Она рабочая и
служит источником семантики для переноса; ссылки на её тесты в плане идут
на коммит `c884c38`.

## Следующие шаги

1. Владелец читает план и одобряет или правит решения.
2. Реализация по плану, задача за задачей, начиная с задачи 1
   (переименование пакета). Каждая задача — коммит и обновление этого
   файла.
3. После задачи 20 — пакеты готовы к публикации; публикация только по
   правилам `AGENTS.md`, отдельным запросом владельца.
