# Регистрация делается в момент прихода значения

Решение владельца 2026-09-15: из трёх выходов взять второй — параметр
у `ctx.run`. Первый (назвать границей и записать обход) отвергнут замером:
обход не теряет проверку правил домена, а отменяет её. Третий (вернуться
к отменённой спеке переноса владения) владелец просил взвесить заново после
этой работы.

## Что было дыряво

`_awaitChild` был устроен так:

```dart
final value = await child.value;
if (!_owner.bodyEnded) check();

return value;
```

Ребёнок кончился `Done` — значит свою условную регистрацию он уже отбросил,
по правилу «регистрация решается исходом того, кто её сделал». Значение у ядра
в руках, и тут контрольная точка бросает. Значение улетает вместе с броском:
до получателя оно не дошло, регистрировать ему нечего, ресурс не закроет никто.

Дыра уже, чем казалась сначала. Обычная отмена значение не теряет: тело
кончается броском из `wait`, `bodyEnded` становится истиной, контрольная точка
пропускается, и `_keepLate` доносит значение до `discard`. Теряет ровно отказ
самой контрольной точки — правило домена, сказавшее «нет» в тот момент, когда
значение уже пришло. В `solo` это `keepWhile`: `_checkedState` отменяет
и бросает прямо там.

Замер на ядре, где место правила занимает `CheckingJob.rules`, взведённый хуком
`onFinish` ребёнка:

```text
recipe:    parent=Cancelled(handler: keepWhile) child=Done(db) closed=[]
two lines: parent=Cancelled(handler: keepWhile) child=Done(db) closed=[]
detour:    parent=Done(db) child=Done(db) closed=[]
```

Третья строка — это обход из первого выхода (`ctx.run(child).ignore()` плюс
`ctx.wait(() => child.value, discard: ...)`). Ресурс он закрывает, но родитель
кончается `Done`: правило домена не спросили вовсе, и задание довело работу
до конца там, где `keepWhile` его останавливал. Обход не теряет проверку правил
— он её отменяет, и в документ такое писать нечего.

## Что сделано

`ctx.run` принимает `dispose:` и `discard:` — те же, что у `ctx.wait`,
с теми же правилами: `dispose` выполняется при любом исходе, `discard` — только
если значение никому не досталось, оба вместе — `ArgumentError`. Отказ
бросается до `startChild`, чтобы за ним ничего не осталось работать.

```dart
final db = await ctx.run(connect, discard: (db) => db.close());
```

Регистрация делается в момент прихода значения, до контрольной точки:

```dart
final value = await child.value;
if (_owner.bodyEnded) {
  await _keepLate(dispose, discard, value);
} else {
  _keepOnStack(dispose, discard, value);
  check();
}

return value;
```

Обе ветки — уже существующие помощники `wait`, так что поздний результат (тело
ушло раньше, чем ребёнок кончился) убирается так же, как у `wait`: на стек,
пока задание ещё разматывается, и на месте, если оно уже кончилось.

## Сторожа

Пять тестов в `cleanup_test.dart`:

- дыра закрыта: правило отказывает в той самой точке — родитель кончается
  `Cancelled`, а ресурс закрыт регистрацией получателя;
- `dispose` у `run` выполняется при любом исходе, `discard` — только когда
  значение не ушло дальше (четыре входа);
- поздний результат убирается и тогда, когда тело ушло раньше;
- оба параметра вместе — `ArgumentError`, и ребёнок не стартовал;
- `disown` снимает запись, сделанную через `run`.

Мутации, каждая краснит ровно свой тест: регистрация после контрольной точки
вместо «до»; ветка позднего результата выброшена; `discard` записан как
`dispose`.

Пример из `doc/cleanup.md` в тесте «a receiver that registered on arrival»
переписан на новую форму — он цитирует документ и должен цитировать то, что
в нём теперь написано.

## Документы

`doc/cleanup.md`: рецепт стал `ctx.run(connect, discard: ...)`, и абзац после
него объясняет, почему параметр стоит на самом вызове, а не строкой ниже.
Дырявая версия примера осталась рядом — теперь две версии отличаются ровно
одним параметром. `doc/children.md`: ветка, получившая ресурс от своего
ребёнка, регистрирует его тем же `ctx.run(opener, discard: ...)`. Переводы
поправлены в том же коммите.

`CHANGELOG` `async_job` — ломающая строка: новые именованные параметры у члена
`abstract interface class JobContext`. Для вызывающего не ломается ничего:
`ctx.run(child)` как был, обёртка
`ctx.wait(() => ctx.run(child), discard: ...)` работает и остаётся верной.
Ломается рукописная реализация `JobContext` — в этом же выпуске она уже
ломается один раз, `runAll` добавлен в тот же интерфейс.

## Чего не делалось

`runAll` параметров не получил: у группы своя механика — регистрации веток
снимает сама группа, когда коммитит. `wait`-обёртка не объявлена устаревшей
и работает по-прежнему.
