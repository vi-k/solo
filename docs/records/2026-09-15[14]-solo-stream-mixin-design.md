# Стрим переезжает в миксин, база забирает имя пакета

Решение владельца 2026-09-15: миксин, стрим в пакете остаётся.

## Зачем

`SoloBase` врёт именем. Суффикс `Base` означает «меня не наследуют, наследуют
моего конкретного потомка» — так у `BlocBase`. Здесь наоборот: базовый класс
и есть то, что наследуют, а потомок добавляет один геттер.

Счёт по живым артефактам, без `docs/records`:

- `extends Solo<` — 74 вхождения, `extends SoloBase<` — 15;
- код, читающий `.stream` у контроллера, — восемь мест, и все одного сорта:
  `close_test`, `closed_state_test`, `hooks_test`, `sequential_test` — тесты
  самого стрима, один пример в `doc/state.md` и абзац README. Вне тестов
  и витрины потребителей нет; в `packages/solo/example` стрима нет вовсе;
- `Solo` держит `final _controller = StreamController<S>.broadcast()` —
  не лениво, на каждый экземпляр. Семьдесят четыре объявления платят за то,
  чего не трогает ни одно.

Иерархия уже проголосовала до этой спеки: `SoloListenable extends SoloBase`,
стрима у него нет, и это было отдельной ломающей правкой.

Вторая причина — развилка. Сегодня `Solo` и `SoloListenable` братья, поэтому
иметь одновременно `stream` и `ValueListenable` нельзя. Миксин это снимает.

## Что получается

```dart
// lib/src/solo.dart  (сегодня solo_base.dart)
abstract class Solo<S extends Object> { /* движок, как сейчас */ }

// lib/src/solo_stream.dart  (сегодня solo.dart)
mixin SoloStream<S extends Object> on Solo<S> {
  final _controller = StreamController<S>.broadcast();
  Future<void>? _closed;

  /// Every state change, in order, delivered on the next microtask.
  Stream<S> get stream => _controller.stream;

  @override
  Future<void> close({SoloCloseMode mode = SoloCloseMode.cancel}) {
    /* тело нынешнего Solo.close без единой правки */
  }

  @override
  void publish(S previous, S current) {
    /* тело нынешнего Solo.publish без единой правки */
  }
}
```

Три формы на стороне пользователя:

```dart
final class Profile extends Solo<ProfileState> {}                      // без стрима
final class Feed extends Solo<FeedState> with SoloStream<FeedState> {}  // со стримом
final class Screen extends SoloListenable<S> with SoloStream<S> {}      // и то и другое
```

Третья сегодня невозможна.

## Замеры

Миксин написан против нынешней базы под её старым именем и запущен — механика
переносится дословно, ни одна строка `Solo` не потребовала правки.

- `stream saw [1, 2], currentState 2` — публикация кормит стрим;
- `after close: stream done = true, isFinished = true` — стрим закрывается
  после движка, порядок сохранён;
- `close() twice returns the same future: true` — мемоизация через `_closed`
  в миксине работает так же;
- `two mixins: log [logged 1], stream [1]` — два миксина, оба переопределяющие
  `publish`, складываются по порядку в `with`.

Комбинация, ради которой миксин и выбран, проверена тестом в `flutter_solo`:
`class Both extends SoloListenable<int> with SoloStream<int>` компилируется,
остаётся `ValueListenable<int>`, и обе доставки живы — слушатель получает
значение внутри изменения, стрим на микротаске.

## Что меняется в дереве

Переименование файлов делается в два шага, иначе имена столкнутся: сперва
старый `src/solo.dart` уезжает в `src/solo_stream.dart`, затем
`src/solo_base.dart` занимает освободившееся `src/solo.dart`. Экспорт
в `lib/solo.dart` называет оба.

Рукописная поверхность:

- `packages/solo/lib/src` — девять файлов упоминают `SoloBase`;
- `packages/solo/test` — восемнадцать файлов, тридцать прямых `Solo<...>(...)`
  и восемь мест со стримом;
- `packages/solo/example` — три файла;
- `packages/flutter_solo/lib/src` — четыре, `test` — три;
- README четырёх штук: два пакета на двух языках;
- `docs/architecture.md` — строки 25–26, 267 и 310;
- страницы `state.md`, `errors.md`, `testing.md`, `flutter.md`, `vs-bloc.md`
  и их русские копии;
- `CHANGELOG` обоих пакетов.

Сгенерированный `doc/api/**` лежит под гитом — его перегенерировать дартдоком,
руками не трогать.

Стенды `vs-bloc.md` и `accumulation.md` компилируют свои фрагменты в CI,
поэтому ошибку в примерах этих двух страниц поймает гейт. У остальных страниц
такой защиты нет.

## Риски

**Тихая потеря стрима.** После переименования все 74 `extends Solo` продолжают
компилироваться и молча теряют `.stream`. Значит, каждое просматривается,
а не предполагается; восемь мест, читающих стрим, переводятся
на `with SoloStream`. Это главный риск правки, и он не ловится компилятором
в тех файлах, где стрим не читают.

**Порядок миксинов.** `publish` и `close` теперь могут переопределяться
несколькими миксинами, и порядок в `with` решает. Сегодня порядок задан
иерархией и выбора нет. Померено выше; в дартдок миксина это надо сказать.

**Инстанцируемость.** Открытый вопрос ниже.

## Открытый вопрос: `Solo` абстрактный или нет

`SoloBase` сегодня `abstract`, а `Solo` — нет, и тесты инстанцируют
`Solo<int>(0)` тридцать раз. После переименования инстанцируемого контроллера
не остаётся вовсе: `Solo` унаследует `abstract`, а `SoloStream` — миксин.

Абстрактных членов у `SoloBase` нет: `abstract` здесь только запрет на прямое
создание, не обязательство типа.

**Предлагаю снять `abstract`.** Сегодня контроллер по умолчанию создаётся
напрямую, это живая возможность, и `run`, `job`, `add` публичны — форма уже
разрешена. Убрав конкретного потомка, эту роль надо отдать базе.

Довод против: тезис пакета — «состояние принадлежит контроллеру, операции это
его методы», и ни один пример в документации `Solo(...)` напрямую не создаёт.
Если решение будет «оставить `abstract`», цена — фикстура в две строки
и тридцать мест в тестах.

## Критерии приёмки

- `SoloBase` не встречается ни в одном живом артефакте;
- `class X extends SoloListenable<S> with SoloStream<S>` компилируется и даёт
  обе доставки — под тестом в `flutter_solo`;
- `close` миксина держит оба сегодняшних обещания: стрим закрывается после
  движка и повторный `close` отдаёт ту же future — под тестами в `solo`;
- восемь мест со стримом переведены на миксин; остальные вхождения
  `extends Solo` просмотрены поимённо, и про каждое сказано, что стрим ему
  не нужен;
- наборы не меньше нынешних: `solo` 577, `async_job` 388, пример 9,
  `flutter_solo` 87;
- оба стенда зелёные, `check_translations`, `check_line_width`,
  `check_doc_shape`, сборка сайта;
- `CHANGELOG` обоих пакетов называет ломающую правку и показывает три формы
  наследования;
- `doc/api/**` перегенерирован.
