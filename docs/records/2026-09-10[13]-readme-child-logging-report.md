# Ожидание дочернего Job

Владелец спросил, можно ли автоматически проверять отмену родителя после
завершения ребёнка, как в join. Сейчас ctx.run синхронно запускает ребёнка
и возвращает тот же хэндл; Job.value передаёт исход ребёнка всем читателям.
Успешный ребёнок может отказать отмене и вернуть значение, хотя родитель
уже отменён. Подмена этого значения отменой родителя внутри общего value
изменила бы контракт для внешних читателей тоже.

Существующий ctx.join(() => child.value) ждёт ребёнка и проверяет отмену
родителя после получения значения. Эта форма показана в примере README,
вместо рекомендации самостоятельно вызвать ctx.check после ожидания.
Отказ ребёнка от отмены не прекращает ожидание. Если ребёнок успешно
завершится, join бросит принятую отмену родителя, и тело не перейдёт
к следующему действию. Ошибка ребёнка передаётся обычным путём через value.

Реализация не менялась. Вопрос о новом ожидании, привязанном к родителю,
или изменении самого value не считается согласованным изменением API.
Обсуждение timing остаётся на этапе согласования отдельной спецификации.

# Примеры ресурсов и логирования

В примере самостоятельного закрытия курсора функция снятия регистрации
переименована из remove в removeDisposer, включая её вызов.

Пример JobObserver дополнен onLog: он распознаёт Object? Function(),
вызывает колбэк и форматирует возвращённые данные. Ниже показан вызов
ctx.log(() => 'migration failed: $error'). Без наблюдателя колбэк никто
не вызывает, поэтому интерполяции нет. README явно отделяет соглашение
наблюдателя от поведения ctx.log, который передаёт объект без изменений.

Английский оригинал и русский перевод изменены вместе. В каждом теперь
19 блоков кода. Новых зависимостей или изменений библиотечного кода нет.

# Проверки

Одноразовый стенд находится в
/private/tmp/async-job-readme-check-20260910/. Он использует локальный
async_job и уже установленные зависимости. Класс наблюдателя извлечён
непосредственно из изменённого README. Анализатор не нашёл замечаний.

Четыре сценария FakeAsync прошли:

- Обычный await child.value после принятой отмены родителя: ребёнок
  отказывает отмене, завершается Done, тело родителя продолжается.
- ctx.join вокруг child.value при тех же условиях: ожидание сохраняется
  до конца ребёнка, но тело родителя не переходит к следующему действию.
  В обоих сценариях родитель завершается Cancelled, внешний читатель
  получает значение ребёнка 3.
- Ленивое сообщение без наблюдателя: toString ошибки не вызывается.
- С наблюдателем из README: toString вызывается один раз, готовая строка
  попадает в журнал; исход Job остаётся Done.

Проверены пять пар переводов, общая ширина Markdown, отдельно AGENTS.md
и этот отчёт, а также git diff --check. Полный набор пакетных тестов
не запускался: изменены документы, поведение проверено стендом.
