# Первые попытки на странице отмены

Владелец 2026-09-18: «давай разберём cancellation в новой ветке. что там
с граблями?» Граблей не было ни одной: вступление — карта четырёх контрольных
точек, и каждый раздел открывался правильным кодом. Разбор кандидатов с зондом
лёг в `main` коммитом `c796b92`; на предложение взять четыре раздела и три
дефекта прозы владелец ответил «все».

## Что сделано

| Раздел | Первая попытка | Чего стоит |
| --- | --- | --- |
| `Stopping the underlying operation` | `ctx.wait` вокруг `seek` | все три перемотки на устройстве сразу; состояние верное |
| то же, вторая | `ctx.join` без токена | проскоченная перемотка идёт до конца, её `Job` всё равно `Cancelled` |
| `Protecting a step or a whole job` | два `ctx.join` | платёж прошёл, журнал не начат |
| `Ordinary await and context lifetime` | голый `await` в цикле, `join` в уборке | `close()` ждёт все куски; сброс не происходит ни при каком исходе |
| `Cancelling and closing a controller` | простой `close()` при очереди | две пачки не уходят, ушедшая первая — `Cancelled(closed)` |
| то же, `Closing from a job` | `await close()` в теле | не возвращается |

Вступление говорит, чем различаются заголовки, как в `state.md`. Раздел
`Protecting` разделён на `One section for the step` и `A whole job`:
у `cancellable: false` своё требование, и под одним заголовком с ответом
на первую попытку оно читалось как второй ответ на неё же.
`Cancellation details` остался справочником.

Три дефекта прозы исправлены там же:

- пустой `ctx.check()` перед `join` в цикле загрузки убран; вместо него проза
  говорит, что `join` проверяет и до операции, и после, а `check()` нужен
  промежуткам после голого `await` и секции `uncancellable`. Абзац `state.md`,
  который ссылается сюда за этими промежутками, теперь находит их названными;
- причина голого `await` в уборке — тело к ней уже закончилось, а не «метод
  отвергает отменённую задачу»: `join` в функции уборки бросает `StateError`
  и на `Done`;
- «`join` suits ... resource release» заменено на «opening a device».

## Сторожа

`packages/solo/test/cancellation_rakes_test.dart`, 18 тестов: 17 при письме
и один по чтению владельца. Устройство — фейк на `Completer`: каждый вызов
идёт, пока тест его не завершит, поэтому трассы детерминированы, без таймеров.
Набор `solo` — 617 (было 599).

Каждый сторож проверен мутацией движка: мутация на копии файла, прогон, возврат
копией, `git status` чист после каждой. Раннер —
`.artifacts/2026-09-18-cancellation-rakes/mutations.py` основной копии.

| Мутация | Краснеет |
| --- | --- |
| `wait` дожидается вызова | перемотки через `wait` |
| `join` не проверяет после вызова | два `join` |
| `join` не проверяет до вызова | `join` после голого `await` |
| `ctx.onCancel` не вызывается | токен; секция |
| `emit` не проверяет до записи | `emit` между голыми `await` |
| секция ничего не держит | секция |
| уборке доступны члены тела | оба `join` в уборке |
| `close()` не ждёт работающую | цикл загрузки, ответ загрузки, `close()` из тела и из уборки |
| `drain` сбрасывает очередь | `drain` |
| `restart` не чистит очередь | перемотки через `join` |
| `close()` на пустом не завершается | метод контроллера |
| `cancelAll()` не ждёт | `cancelAll()` из тела |
| `close()` не завершает стоявшие в очереди | `close()` при очереди |
| секция бросает на выходе | конец секции |
| удержанная отмена не применяется | конец секции; секция |

Без своей мутации один сторож: голые `await` доводят оба вызова платежа. Это
свойство Dart, а не движка, — прервать `await` снаружи нечем.

Два счёта нашлись на мутациях. Первый: без проверки после `join` сторож двух
`join` оставался зелёным — вторую проверку делает вход следующего `join`,
и по трассе устройства их не различить. Между вызовами поставлена метка теста,
и её отсутствие говорит, что бросил именно первый. Второй: исход ушедшей пачки
остаётся `Cancelled(closed)`, даже если снять и проверку после `join`, и выбор
исхода по пометке, — его держит больше одного механизма. Проза поэтому
объясняет исход тем, что `Job` приняла отмену до того, как пачка дошла,
а не устройством `join`, которого в примере к тому же нет.

## Слова

Два места нашлись перечитыванием. В разделе про перемотку «seek» называл
то вызов устройства, то задачу: `restart` «отменял перемотку», а завершалась
`Job`. Теперь перемотка — вызов, а задача — job и `Job`. В первой попытке
закрытия проза объясняла исход через `join`, которого в примере нет: как
устроен `send`, читатель не видит.

## Чтение владельца

2026-09-18, таблица вступления: у `ctx.join(action)` было «checks cancellation
before returning a successful result» — что `join` при этом бросает
`Cancelled`, читатель должен был вывести сам. Строка говорит теперь прямо:
дожидается операции, затем бросает `Cancelled` вместо успешного результата.
Абзац первой попытки платежа ссылается на эту строку, и повтор «бросает
`Cancelled`» в следующей фразе из него убран. Утверждение держит сторож двух
`join`: метка между вызовами пропадает, только если бросил первый.

Там же, строка `ctx.uncancellable(action)`: было «the next checkpoint throws
it», и из этого не следовало, что сама секция `Cancelled` не бросает. Строка
говорит теперь, что секция возвращает результат действия без `Cancelled`, код
после неё выполняется до следующей контрольной точки, и бросает уже она. Под
это встал новый сторож «the end of a section»: секция, метка, `ctx.check()`,
метка. Две мутации его краснят — секция, бросающая на выходе, и удержанная
отмена, которая не применяется вовсе.
