# План изменения ctx.run

Исполнение: superpowers:subagent-driven-development, задачи по областям
файлов; основной агент ведёт документы, проверяет интеграцию и коммитит
общий результат. Работа в main по AGENTS.md, без отдельного worktree.

Цель: `final rows = await ctx.run(child)` ждёт ребёнка и проверяет отмену
родителя, без отдельного ctx.join. Исходный child остаётся хэндлом.

Основание: предложение в
`2026-09-10[13]-readme-child-logging-report.md` и ответ владельца
«тогда да, делай как предложил» после уточнения идентичности хэндла.

## Контракт и ограничения

- `Future<T> run<T>(Job<T> child)` запускает существующий Job сразу;
  новый Job или публичную обёртку не создаёт.
- Существующая синхронная проверка допустимости запуска сохраняется:
  ошибки владения, жизненного цикла и уже принятой отмены бросаются
  при вызове. После запуска результат и ошибка ребёнка идут через Future.
- Ожидание включает детей и уборку ребёнка. После успешного результата
  вызывается виртуальный check родителя, как в join. Ошибка или Cancelled
  ребёнка передаются со своим стеком; исход самого ребёнка не меняется.
- Если отмена пришла во время запуска, run всё равно подписывается на
  результат ребёнка и дожидается его, включая отказ от отмены.
- Ожидание, которое тело не дождалось, ведёт себя на успешном пути как
  join после конца тела: не проверяет закрытый контекст. Future всё равно
  требует обработки ошибок; `.ignore()` обозначает осознанное игнорирование.
- each по-прежнему возвращает Job<void> немедленно и сам не наблюдает
  его исход. Выделить защищённый startChild для синхронного усыновления,
  запуска и прежних проверок; run и each используют его.
- SoloContext наследует новый результат run, а проверку владения
  переносит в startChild. SoloBase.run, Job.then, each и версии неизменны.
- Не менять другие правила отмены, cleanup и ненаблюдённых ошибок.
- Dart SDK ^3.6.0; новых зависимостей нет. Тесты через FakeAsync.
- Код и публичные документы по-английски, переводы меняются вместе;
  рабочие документы по-русски, ширина 79. Push и публикации нет.
