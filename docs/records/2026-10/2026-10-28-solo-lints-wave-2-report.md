# `solo_lints`, вторая волна: отчёт

## Что сделано

Пакет `packages/solo_lints` получил два правила, три быстрых исправления
и сторож страницы ошибок. Зависимость одна новая:
`analyzer_plugin: '>=0.14.8 <0.15.0'`, без неё продюсеры исправлений
не собираются. Работа шла от `c9f6fd29`, по задаче с независимым ревью
на каждую; после ревью каждой задачи шли отдельные коммиты правок.

1. Стенд исправлений и `AddCheck`, исправление `catch_without_check`:
   `66f13f90`, правки ревью `614e08d0`. Исправление молчит, когда параметр
   исключения или трассы стека `catch` либо локальная переменная в его блоке
   носит имя контекста. `assertFix` сверяет `fixArguments` и анализирует
   исправленный текст заново: диагнозов не должно остаться вовсе.
2. `PassReleaseToCall`, исправление `release_on_the_call`: `0e186dbc`, правки
   ревью `ff792a67` и `56db0c31`. Исправления нет у вызова без аргументов
   и у литерала с необязательными параметрами; обход инструкций вынесен в общий
   `statementsOf`; тесты исправлений переведены на публичное API анализатора,
   а `assertNoFix(..., otherDiagnostics: true)` принимает код с ошибкой
   компиляции.
3. Линт `key_per_request`: `55d612c3`, правки ревью `a8b1d36a`. Правило молчит
   на ключе, который читает локальную переменную; добавлены тесты на тело
   локальной функции, `final`-замыкание, `.droppable` и `(Policy.droppable)`.
4. `PutArgumentsIntoKey`, исправление `key_per_request`: `eafa04e6`, правки
   ревью `a20e867f`. Ключ находится по диапазону, поэтому исправление получает
   и ключ-литерал типа; исправление зарегистрировано рядом с правилом.
5. Линт `ignore_failure_hides_bugs`: `f42d575e`, правки ревью `15da4321`. Нет
   падения на `..ignoreFailure().x`; каскад в скобках считается отброшенным.
6. Сторож страницы ошибок `test/mistakes_page_test.dart`: `a83044d9`, правки
   ревью `5ce688d0`. Сторож краснеет с именем раздела на разделе без пары,
   на блоке кода Dart без маркера перед ним, на разном числе «Don't do this»
   и «Do this», на паре вне таблицы и на строке таблицы без пары. Отдельный
   тест показывает, что `ignore_failure_hides_bugs` в стороже включён:
   на странице нет блока, где он сообщает. Мутации страницы и таблицы
   проверены, каждый прогон краснел с именем раздела.
7. Документы: README и перевод, CHANGELOG и перевод, описание в `pubspec.yaml`
   (175 знаков), эта запись, шапки, handoff.

Отдельно — `e5262fa5`, только заметка в handoff.

## Зонд задачи 1 и расхождение с дизайном

Зонд собрал контекст исправления из разрешённой библиотеки теста, запустил
продюсер и применил его правки. Он прошёл на одном публичном API, без `src/`,
и на свежих версиях, и на полу: Dart 3.10.0, `analysis_server_plugin` 0.3.14,
`analyzer` 12.1.0, `analyzer_plugin` 0.14.8, `analyzer_testing` 0.2.5.

**Расхождение, которое нужно принять.** Дизайн писал «сторож и тесты
исправлений вне архива», потому что ждал, что стенду понадобятся внутренности
`src/`. Не понадобились, и по правилу плана тесты исправлений едут в архив
и идут в задании `floor`. Вне архива остался один файл,
`test/mistakes_page_test.dart`: ему нужен `packages/solo/doc/mistakes.md`,
которого в архиве нет, и `.pubignore` его исключает.

Побочное наблюдение: простой `dart pub downgrade` на SDK 3.10 тянет
транзитивный `frontend_server_client` слишком низко и ломает `dart test`.
Задание `floor` понижает только прямые зависимости, и это работает.

## Решения, принятые при исполнении

В дизайне их нет; каждое владелец принимает или отвергает отдельно.

1. `key_per_request` молчит, когда ключ читает локальную переменную
   (`final key = (_Op.load, id); enqueue(key: key, …)`). Правило не следит
   за переменными и не отличит ключ, построенный из параметра, от константы;
   молчание — безопасная сторона. Цена: локальная переменная с постоянным
   ключом не замечается.
2. Тип возврата литерала функции в `ignore_failure_hides_bugs` берётся из его
   статического типа, а не из параметра или переменной, куда литерал идёт: Dart
   выводит `void` из контекста `void`, и результат совпадает с дизайном. Ревью
   проверило `void Function()` параметром, присваиванием, параметром,
   допускающим `null`, `run<void>`, элементом списка и `forEach` — диагноз
   есть; `Object`, `dynamic`, `Function`, обобщённый `T Function()` и `final f`
   без типа — молчание. Известный предел: `async`-литерал в контексте `void`
   (`() async => profiles.load()..ignoreFailure()`) молчит,
   а `async`-объявление с `void` сообщает.
3. `{0}` для голого `enqueueJob(job(…, isExpectedError: …)).ignoreFailure()` —
   «job's isExpectedError», то есть вызов, который несёт предикат. Дизайн этот
   случай не называет.
4. `ignore_failure_hides_bugs` читает поле-накопитель только через неявный
   `this` или `this.x`; `other._saves.add(e)` молчит. Дизайн говорит «поле
   того же класса».
5. Быстрые исправления ничего не строят там, где правка неоднозначна сверх
   перечисленного в дизайне: имя контекста затенено в `catch` (`AddCheck`),
   вызов без аргументов и литерал с необязательными параметрами
   (`PassReleaseToCall`).

## Известные пробелы

- `AddCheck`: нет тестов на однострочный непустой блок и на комментарий
  в строке со скобкой.
- `key_per_request`: `test_body_is_tear_off` проходит по построению — отрыв
  метода не может читать параметр объемлющего.
- `PassReleaseToCall`: удаление инструкции освобождения оставляет комментарий
  её строки в нулевой колонке — это сырая правка до `dart format`.
