## Что сделано

**L20 ядра.** `groups.md` открывается двумя фразами о группе, а потом легендой
вывода: группа — несколько детей одной задачи, которые идут одновременно,
и задача ждёт их всех; `.wait` над future из `ctx.run` даёт каждой ветке дойти
до конца, `ctx.runAll` отменяет идущие ветки, как только одна кончилась без
значения.

**M8 ядра, `observing.md`.** Рецепт для приложения — новый раздел в конце
страницы, «Reporting each error once», и ссылка на него во вступлении.
Наблюдатель `Reports extends JobObserver with JobAnswerer` сообщает
из `onUnanswered`, а зона — через `runZonedGuarded` вокруг `startApp`, функции,
которая запускает приложение; таблица говорит, кто о чём сообщает, и проза —
почему `onError` в отчёте не участвует: он слышит и то, что потом дойдёт
до зоны. Зонд перед правкой: каждая из пяти ошибок сообщается один раз. Стенд —
`Reports` и `reportingOnce` в `test/support/observing_page.dart`, тесты группы
«Reporting each error once» в `observing_rakes_test.dart`: каждая ошибка
сообщается один раз одним из двух мест; `onError` слышит провал, о котором
сообщает и зона. Мутация — `Reports` без `JobAnswerer` — краснит группу.

**M8 ядра, `streams.md`.** Во вступлении код ответа — `ctx.each` с `join`
внутри — и фраза о том, что раздел «Processing a stream» приходит к нему после
трёх попыток, к которым ведёт обычная подписка.

**M8 ядра, `cancellation.md`.** Рецепт и таблица и так стоят в начале страницы.
Таблица маршрутов в конец `observing.md` не переносилась: она уже есть
на странице, и вторая копия разошлась бы с первой.

**M8 ядра, dartdoc.** Контракт первым абзацем:

- `JobObserver.onError`: сюда приходит каждая ошибка, которую ловит задача,
  кроме `Cancelled`, которым задача кончается; хук только слышит, и его
  переопределение ошибку никуда не переносит. Прежнее «Notification only:» ниже
  ушло;
- `JobAnswerer.onUnanswered`: ответ — то, что делает хук; по умолчанию ошибка
  уходит в зону создания, а переопределение без `super` её туда не пускает;
- `Job.ignoreFailure`: провал не доходит ни до зоны, ни до `onUnanswered`;
  `onError` его слышит.

У `join`, `abandonable` и `run` первый абзац и так говорил контракт.
`extending.md` в этой волне не трогался: полный листинг движка он получил с M3
в третьей волне.

**M9 solo, карта чтения.** В README `solo`, раздел «Guides», после ссылки
на сайт: первые три страницы — для любого контроллера, по порядку: задачи,
состояние, отмена; следующие четыре — когда контроллеру нужно то, о чём они:
ресурсы, дети, стримы, накопление; ошибки и тестирование — перед выпуском,
частые ошибки — список для сверки, справочник называет каждый член
с объясняющим его разделом; Flutter — для контроллера за экраном, пример камеры
собирает страницы в одном контроллере, сравнение с bloc — для того, кто пришёл
из bloc. С переводом.

**M9 solo, `errors.md`.** После вступления — таблица разделов по тому, что
нужно приложению: отчёт о каждой ошибке, провал вне зоны, ответ за ошибку без
исхода, `catch`, пропускающий отмену, повтор, отказ правила, фоновая работа,
лог всех контроллеров, что держит `close()`, задачи, которые шли дальше своей
отмены. В каждой строке — член, который это даёт, и ссылка на раздел.

**M9 solo, `accumulation.md`.** Вступление раздела «Recipes» получило таблицу
четырёх рецептов: что доходит до работы и чем собран накопитель — фабрика,
`merge`, `timing`, `policy`.

**M9 solo, `flutter_solo`.** В конце «Usage» README — таблица выбора UI API:
`SoloBuilder` или `ValueListenableBuilder`, `SoloSelector`, `SoloSelection`,
`Listenable.merge`, `listen`. Фраза над таблицей говорит, что таблица называет
все способы, а разделы ниже разбирают остальные.

**L18.** README `flutter_solo`: «Install» показывает второй импорт,
`package:flutter_solo/listenable.dart`, со ссылкой на «Methods from a second
import». Абзацы о `changed:` переставлены: сначала что сравнивается — последний
выбор, принятый виджетом, как `previous`, и новый, — потом о замыканиях
на месте. Сторож в `readme_rakes_test.dart` держит новую фразу.

**L21.** README `flutter_solo`: пример `ListenableBuilder` над
`Listenable.merge([left, right])`. Код — `mergedBuilder`
в `test/support/readme_widgets.dart`, тест «the widget over two profiles
rebuilds when either changes» — профили грузятся в обоих порядках, так что
виджет должен услышать каждый; счётчик блоков Dart в README — 15.

Таблицы и карта чтения кода не содержат, стенды их не держат; ссылки таблиц
сверяет `tool/check_links.py`. Все правки оригиналов переведены тем же
коммитом.

## Ревью

Opus в отдельной копии дерева, отвязанный worktree на `4f8d4ee4` с волной
поверх. Ревьюер прогнал гейт ядра, тесты страниц `solo` и README
`flutter_solo`, проверки документов, сверил обе таблицы входа построчно
с разделами, гонял свои зонды в пакете ядра и мутации. L18 и L21 он признал
закрытыми, L20 — закрытой после правки формулировки, M8 и M9 — частично;
расхождения с вердиктами — вход страницы вместо начала раздела, таблица
маршрутов на месте, `extending.md`, длинные фразы — обоснованными. Его находки,
все исправлены этим же коммитом:

1. Medium. Новый первый абзац dartdoc `onError` говорил, что ошибка идёт
   туда же, куда шла бы без наблюдателя. У наблюдателя, который отвечает, она
   идёт в `onUnanswered`, а без наблюдателя — в зону: его зонд печатает
   `zone: Bad state: four` без наблюдателя и `onUnanswered: Bad state: four`
   с ним. Теперь «The hook only hears it: overriding it moves the error
   nowhere».
2. Medium. Итоги не дописаны в вердикты M8, L20, M9, L18, L21. Дописаны.
3. Low. Dartdoc `ignoreFailure`: «the outcome keeps it» неверно для провала
   тела задачи, которая кончилась `Cancelled`, — исход хранит отмену. Хвост
   снят.
4. Low. Сторож L21 пропускал мутанта `Listenable.merge([right])`: правый
   профиль грузился последним. Тест грузит профили в обоих порядках.
5. Low. Отчёт не был залит. Залит.
6. Low. Строка таблицы `observing.md` об ошибках без исхода читалась полным
   списком. Теперь «such as», с переводом.
7. Low. `runZonedGuarded(runApp, …)` у читателя Flutter не собирается: его
   `runApp` берёт виджет. Функция названа `startApp`, и фраза под блоком
   говорит, что это, с примером `() => runApp(const App())`; стенд переименован
   так же.
8. Low. Вступление `groups.md` говорило «the body waits for all of them» и «as
   soon as one fails». Теперь ждёт задача, а `runAll` отменяет ветки, как
   только одна кончилась без значения, — как говорит сама страница.
9. Мелочи. В README `flutter_solo` «that pick» стало `previous`, со сторожем;
   фраза над таблицей UI API больше не называет таблицу «другими способами»;
   строка `listen` говорит «with `SoloListenable`»; в переводе `observing.md`
   «хватит раздела» стало «начинает с раздела».

Ещё он отметил, что карта чтения README `solo` молчит о трёх последних строках
таблицы: Flutter, Camera example и `vs-bloc.md`. Дописана фраза о них,
с переводом; сама страница `vs-bloc.md` не тронута.

Повторного ревью правки по его находкам не было; находки 4 и 9 держат сторожа.
