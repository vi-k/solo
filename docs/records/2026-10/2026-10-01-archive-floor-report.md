## Что сделано

`tool/archive_floor.py`, два шага под два SDK.

- `stage <каталог>` раскладывает по пакетам файлы, которые загрузил бы
  `dart pub publish`. Состав печатает сам `pub` с `--dry-run`; опции
  `--to-archive` у него нет. Из `dev_dependencies` раскладки убираются `lints`
  и `flutter_lints`, а `pubspec_overrides.yaml` из дерева копируется рядом.
  Каталог внутри репозитория скрипт не берёт: следующий dry-run внёс бы его
  в архив.
- `run <каталог>` идёт по раскладке с SDK из PATH: `pub get`, `pub downgrade`
  для прямых зависимостей с pub.dev, `analyze lib`, тесты, затем то же для
  примера и запуск его программы. Перед этим сверяет SDK с полом
  из `pubspec.yaml` и на другом краснеет; `--any-sdk` снимает сверку для
  ручного прогона.

Гейт: задание `flutter` получило шаг раскладки и отдаёт её артефактом, новое
задание `floor` ставит Flutter 3.27.0 с его Dart 3.6.0, забирает артефакт
и гоняет `run`. Шаги разнесены по заданиям из-за SDK: dry-run разрешает пакет
вместе с линтами, которым нужен Dart 3.8, а Flutter-пакет — только с Flutter
в PATH; такой SDK уже стоит в задании `flutter`. Задание `docs` гоняет сторож
скрипта. Версии экшенов взяты командой: `upload-artifact` v7,
`download-artifact` v8.

Описание — раздел «Проверки» `AGENTS.md`, строка в `docs/conventions.md`
и шапка `gate.yml`.

## Сторожа

`tool/archive_floor_test.py`, 16 тестов: разбор дерева dry-run (вложенные
каталоги, каталог не файл, конец дерева, имя с пробелами и скобками), снятие
линтов, выбор зависимостей для `downgrade` (ограничение — да, карта, оверрайд
и dev — нет) и сверка пола (пол, свежий Dart, свежий Flutter, поднятый
в `pubspec.yaml` пол, чистый Dart-пакет, Flutter нет в PATH).

Семь мутаций скрипта, каждую сторож ловит: стек каталогов не снимается; конец
дерева не замечен; размер не обязателен; оверрайды не исключаются; линты
остаются; любой SDK сходит за пол; пол Flutter не читается.

  а не против pub.dev.
