## Что сделано

`tool/archive_floor.py`, два шага под два SDK. Ниже — как скрипт устроен после
ревью.

- `stage <каталог>` раскладывает по пакетам файлы, которые загрузил бы
  `dart pub publish`. Состав печатает сам `pub` с `--dry-run`; опции
  `--to-archive` у него нет. Что dry-run сказал о пакете, печатается, а код
  возврата судится: предупреждение роняет шаг. Из `dev_dependencies` раскладки
  убираются `lints` и `flutter_lints`, а `pubspec_overrides.yaml` из дерева
  копируется рядом. Каталог — новый, пустой или с меткой прежней раскладки,
  `archive_floor.txt`; каталог внутри репозитория, каталог над ним и чужой
  непустой скрипт не берёт и ничего в них не удаляет.
- `run <каталог>` идёт по раскладке с SDK из PATH, дважды по каждому пакету
  и его примеру. Как по зависимости: `pubspec.yaml` без `dev_dependencies`,
  `pub get`, `pub downgrade` для прямых зависимостей с pub.dev, `analyze lib`
  только на ошибки, программа примера. Потом с тестами: dev-зависимости
  на месте, тот же `downgrade`, набор. После каждого `downgrade` читается
  `pubspec.lock`: зависимость выше нижней границы — красный. Пакет без тестов
  в архиве — красный. Упавший шаг печатается целиком. Перед всем этим скрипт
  сверяет SDK с полом из `pubspec.yaml` и на другом краснеет, как и на поле,
  который не смог прочитать; `--any-sdk` снимает сверку для ручного прогона.

Гейт: задание `flutter` получило шаг раскладки и отдаёт её артефактом на семь
дней, новое задание `floor` ставит Flutter 3.27.0 с его Dart 3.6.0, забирает
артефакт и гоняет `run`. Шаги разнесены по заданиям из-за SDK: dry-run
разрешает пакет вместе с линтами, которым нужен Dart 3.8, а Flutter-пакет —
только с Flutter в PATH; такой SDK уже стоит в задании `flutter`. Задание
`docs` гоняет сторож скрипта. Версии экшенов взяты командой: `upload-artifact`
v7, `download-artifact` v8.

Описание — раздел «Проверки» `AGENTS.md`, строка в `docs/conventions.md`
и шапка `gate.yml`.

## Сторожа

`tool/archive_floor_test.py`, 54 теста. Чистые функции: разбор дерева dry-run,
снятие линтов и dev-зависимостей, выбор зависимостей для `downgrade` с нижней
границей каждой, чтение `pubspec.lock`, сверка пола во всех формах записи.
Оркестровка — на временном дереве из двух пакетов, с SDK, подменённым
записывающей заглушкой: что `stage` кладёт и чего не удаляет, какие команды
и в каком порядке `run` зовёт в каждом корне, что красный шаг, зависимость выше
границы, архив без тестов, чужой SDK и каталог без метки — красные, и что
единственный вызов `publish` — с `--dry-run`.

Тридцать две мутации скрипта, каждую сторож ловит. Среди них те, что ревью
нашло незамеченными в первой версии: `stage` не снимает линты, не копирует
оверрайды, берёт каталог в репозитории; `run` пропускает `downgrade`, анализ,
тесты, пример или программу, не записывает упавший корень, выходит с нулём при
красном.

## Независимое ревью

Ревьюер Opus в копии дерева на `2e7018b`. Состав архива он сверил со списком
скрипта файл в файл своим разбором и `git ls-files`, пути
в `package_config.json` раскладки — что ведут в раскладку, а не в дерево, входы
экшенов — по их `action.yml`, Flutter 3.27.0 — по `releases_linux.json`.
Находку H1 я проверил по коду: `out / 'solo'` при `out = ..` — сам репозиторий.
M1 и M4 повторил мутациями дерева, таблица выше; остальное принял по его
прогонам и закрыл сторожами.

1. **High. `stage ..` удалял репозиторий.** Сторож ловил только каталог внутри
   репозитория. Дерево называется `solo`, как пакет, и `rmtree(out / 'solo')`
   при каталоге над деревом сносил его вместе с `.git`; так же сносился любой
   чужой каталог с именем пакета.

   Вердикт: принято, исправлено. `stage` пишет только в новый, пустой или
   помеченный своей меткой каталог и отказывает каталогу над репозиторием; путь
   сравнивается после `resolve()`. Сторожа: родитель дерева, он же через `..`,
   ссылка внутрь дерева, чужой непустой каталог.

2. **Medium. «Без dev-зависимостей» не выполнялось, вердикт dry-run
   выбрасывался.** В раскладке оставались `test`, `fake_async` и прочие: импорт
   dev-зависимости из `lib/` был зелёным везде, хотя сам dry-run на нём выходит
   с кодом 65.

   Вердикт: принято, исправлено. Анализ и программа идут по `pubspec.yaml` без
   блока `dev_dependencies`, для тестов блок возвращается; код возврата dry-run
   судится, его вывод печатается.

3. **Medium. Красный тест не называл ни теста, ни ошибки:** печатались
   последние тридцать строк вывода.

   Вердикт: принято, исправлено. Упавший шаг печатается целиком.

4. **Medium. Никто не сверял, что `downgrade` дошёл до нижней границы.**
   На stable `meta` останавливалась на 1.18.3, а шаг говорил `ok`; разбор блока
   `dependencies` молча терял пакеты на комментарии в нулевой колонке, на CRLF
   и без перевода строки в конце.

   Вердикт: принято, исправлено. `pubspec.lock` читается после каждого
   `downgrade`; `pubspec.yaml` разбирается по строкам, четыре формы —
   в стороже.

5. **Medium. Архив без `test/` — зелёный и пустой.**

   Вердикт: принято, исправлено. Пакет без тестов в архиве — красный, в итоге

6. **Medium. Сторож не держал оркестровку:** двадцать мутаций из сорока двух
