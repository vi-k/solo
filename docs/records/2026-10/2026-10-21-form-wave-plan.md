# Волна формы

## Откуда

Владелец 2026-10-21 взял волну формы до выпуска 0.3.0, обе записи ревью,
вопросы 3 и 5. Проверка, которую он назвал: список членов в отчёте волны
со строками `///` до и после. Сырые отчёты ревьюеров с советами по каждой
странице — `.artifacts/2026-10-21-full-review-3/out/`, раздел 6.

Поведение кода волна не меняет: правятся dartdoc, страницы и их переводы, тесты
страниц и стенды — ровно там, где их держит правленый текст.

## Правила для dartdoc

Для каждого члена из списка ниже:

1. Первый абзац — договор: что член делает, что бросает, одна главная ловушка.
   Первая фраза — короткое резюме, как требует Effective Dart.
2. Один короткий блок кода, если он у члена уже есть или страница его
   показывает; новых примеров не сочинять.
3. Ссылка на раздел страницы абсолютным адресом GitHub `blob/main` по решению
   74, с якорем. dartdoc с сайта на pub.dev ведёт на GitHub так же, как
   английские страницы в соседний пакет.
4. Разбор случаев, который страница повторяет, уходит. Разбор, который есть
   только в dartdoc, остаётся — коротко — или переезжает на страницу, если
   у страницы для него есть раздел; тогда тем же коммитом перевод и тест
   страницы. Каждый удалённый абзац назван в отчёте вместе с местом страницы,
   где сказано то же.
5. Часть тестов читает исходники `lib/` и держит их тексты:
   `readme_recipe_test.dart` и `extending_rakes_test.dart` ядра,
   `state_rakes_test.dart`, `jobs_rakes_test.dart`
   и `protected_operations_test.dart` `solo`, `readme_rakes_test.dart`
   и `solo_listenable_test.dart` `flutter_solo`. Удаляя абзац, найти,
   не держит ли его такой тест; упавший тест значит, что ушла фраза, на которую
   опирается страница или договор, — тогда правится страница или тест
   с объяснением в отчёте, а не молча фраза.

Сторож ссылок: `tool/check_links.py` сейчас читает только Markdown. Волна
добавляет ему проход по `///` в `packages/*/lib/`: ссылка
на `github.com/vi-k/solo/blob/main/...` должна вести на файл дерева и на якорь,
который в нём есть, по тем же правилам, что ссылка страницы. Тест —
в `tool/check_links_test.py`, как у остальных правил. Без него ссылки dartdoc,
которых волна заводит два десятка, ломаются молча при первом переименовании
раздела.

## Порядок и исполнение

Пять частей, каждая — своим коммитом в `main`, в таком порядке:

1. Сторож ссылок dartdoc в `check_links.py` с тестом.
2. Dartdoc ядра.
3. Dartdoc `solo` и `flutter_solo`.
4. Страницы ядра: `extending.md`, `groups.md`, `cleanup.md`.
5. Страницы `solo` и `flutter_solo`: вход, основной путь, длинные фразы,
   «Notes».

Части 2–5 правят разные файлы, и их можно отдать исполнителям параллельно,
каждому — своя копия дерева на вершине `main` этой сессии,
а не на `origin/main`. Каждую часть я читаю целиком до коммита: удалённое
в dartdoc сверяю со страницей сам, по отчёту исполнителя не принимаю.
