## Для ИИ-агентов

**Агент-пользователь — 8,7.** Быстро находятся назначение пакета, образец

пока не хватает: D1 предлагает неверный образец, D2 требует знания, которого
нет в подсказке.

Привычные ошибки, проверенные зондом `probe_review.dart`:

| Привычный код | Что получилось | Защита |
| --- | --- | --- |
| `await job` вместо `await job.done` | `finished=false` | `await_only_futures`, но текст не называет `.done` и `.value` |

## Medium

### D1. Пример `SoloSelection` слушает прежний контроллер

**Нашёл:** Astra (D1). **Где:**
`packages/flutter_solo/lib/src/solo_selection.dart`, dartdoc класса
`SoloSelection`, пример `_ProfileState`.

Пример держит выборку в поле:

```dart
late final canSave =
    SoloSelection(widget.controller, (state) => state.canSave);
```

`didUpdateWidget` нет, и неизменность `widget.controller` не названа условием.
Flutter сохраняет `State` при обновлении виджета того же типа и ключа, поле
инициализируется один раз: действия идут в новый контроллер, а разрешение
на них приходит от старого.

```text
after controller replacement: current=true; buttonEnabled=false
old controller enables button; save goes to new controller
```

Зонд `probe_dartdoc_selection_test.dart` меняет контроллер с `false`
на контроллер с `true`, сохраняя `State`, затем меняет старый и нажимает
кнопку. README, раздел «Selecting one value», замену обрабатывает верно.

Вердикт: принято, Medium: неверный образец в подсказке, которую агент и человек
копируют первой, и тот же класс ошибки, который README уже разбирает. Пример
dartdoc показывает поле вместе с `didUpdateWidget`, как README, или — если
в тридцать строк сторожа это не встаёт — короткую форму с `SoloSelector`
и ссылку на README для поля. Закрепить тестом C1.

### D2. Унаследованный пример ребёнка не годится для `SoloContext`

**Нашёл:** Astra (D2). **Где:** `packages/solo/lib/src/job_context.dart`,
`SoloContext`, унаследованные `run`, `start` и `runAll`; пример
`JobContext.start`.

Пользователь `SoloContext` видит пример ядра:

```dart
ctx.start(Job.deferred<void>((ctx) => sendReport(rows)));
```

Типы его пропускают — сигнатура принимает `ChildJob`, — а `_solo._own`
отвергает ребёнка ядра. Ребёнок нужен из `job(...)` того же контроллера.

```text
run: Invalid argument (job): was not created by this Solo: "Job()"; childFinished=false
start: Invalid argument (job): was not created by this Solo: "Job()"; childFinished=false
runAll: Invalid argument (job): was not created by this Solo: "Job()"; childFinished=false

```

Вердикт: принято, Low: отказ безопасен, но ни подсказка, ни текст ошибки
не называют, чем создать подходящего ребёнка. В dartdoc `SoloContext` —

### D3. `resources.md` исключает синхронную отмену

**Нашёл:** Astra (D3). **Где:** `packages/solo/doc/resources.md`, вступление
«Resources and cleanup» и комментарий перед `device.events.listen`.

Вступление говорит «Cancellation arrives at awaits, not between statements»,
пример — что между синхронным получением подписки и регистрацией уборки ничего
не случается. Но синхронный вызов может вызвать пользовательский код:
`StreamController.onListen` отменяет задачу до возврата из `listen()`.

```text
after listen, before onDispose: cancelled=true
registration after cancellation: released=1
```

Утечки в образце нет: `onDispose` принимает регистрацию на отменённой, но ещё
работающей задаче. Образец безопасен поэтому, а не потому, что отмена
невозможна.

Вердикт: принято, Low. Между синхронными строками не вклинивается событие
очереди, но вызванный код может отменить задачу синхронным колбэком,
и регистрация уборки после этого всё равно принимается — так и сказать. Тем же
коммитом — перевод `docs/ru/solo/resources.md`.

### A1. Карта модулей описывает замену в накопителе неверно
