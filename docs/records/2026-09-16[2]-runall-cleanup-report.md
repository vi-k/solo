## Вопрос

Волна по находкам ревью `async_job` оставила один пункт открытым: `runAll`
не получил `dispose`/`discard`, хотя `run` их получил ради «регистрируй
на прибытии». Находка сама говорила, что гонки нет, и относила решение
к отдельной спеке с кругом ревью — как всякое расширение публичного API в этом
репозитории.

## Разбор

Первое подозрение было о более тяжёлом дефекте: что ветка, уже кончившаяся
`Done`, теряет закрытие своего значения, если группа следом проваливается из-за
соседа, — потому что обычное правило «`Done` — значит отдано» сняло бы
`discard` до решения группы. Проверено зондом
(`.artifacts/2026-09-16-runall-discard-probe/probe.dart`, вне гита): **не
подтвердилось**. Ветка, ещё не дошедшая до `isFinished`, отменяется наравне
с остальными через `_pendingCancel`, и это переворачивает её исход обратно, так
что `discard` всё-таки срабатывает. Dartdoc `runAll`
(`job_context.dart:408-414`) это и обещает: ресурс «closed by the branch itself
when it will not [be given to the caller]». Зонд подтвердил уже написанное
обещание, а не нашёл новое.

Настоящая дыра — на пути успеха. Родитель получает `List<T>` без всякой
регистрации, и «очевидный» способ дописать её руками —
`for (v in values) await ctx.wait(() => v, discard: ...)` — **не работает**.
`wait` начинается с `check()` до вызова действия; если отмена уже стоит,
`action()` не позовётся вовсе, значение не пройдёт через `_keepOnStack`,
а `.ignore()` тихо проглотит ошибку. Двумя зондами (`probe2.dart`,
`probe3.dart`) измерено: цикл с `await` между итерациями теряет все элементы
после того места, где пришла отмена (`closed=[true, false, false]`), а «тесный»
цикл без `await` между регистрациями спасает только от отмены, пришедшей после
него, но не от той, что стоит уже до цикла — тогда не регистрируется ни один
элемент, и на канале отладки не остаётся ни строки
(`closed=[false, false, false]`).

Решение нашлось не в новом параметре, а в существующем публичном API.
`ctx.wait`/`ctx.join`/`ctx.run` — не тот инструмент для значения, которое уже
на руках: они рассчитаны на запуск действия и потому несут его чекпойнт.
`ctx.onDispose`/`ctx.onDiscard` не запускают никакого действия и ничего
не проверяют — они просто кладут замыкание на стек чистки. Зонд (`probe4.dart`)
подтвердил: тот же сценарий с отменой, стоящей до регистрации, —
`closed=[true, true, true]`.

```dart
final values = await ctx.runAll(branches);
ctx.onDispose(() {
  for (final value in values) {
    value.close();
  }
});
```

## Решение

`dispose`/`discard` у `runAll` не нужны: родитель уже сегодня — новый владелец
списка, и `onDispose`/`onDiscard` дают ему безопасную регистрацию без единого
окна гонки. Пункт закрыт документацией, а не кодом: абзац и пример добавлены
в `packages/async_job/doc/children.md` и перевод, следующей же строкой после
`ctx.runAll`, с явным предупреждением про `ctx.wait(() => value, discard: ...)`
как неверный инструмент для этого случая. Спека и круг ревью не понадобились —
публичный API не меняется.
