# Изменение API

Владелец одобрил замену future регистрацией и передачу причины:

```dart
final unregister = job.whenCancelled((cancelled) {
  print(cancelled.reason);
});
```

Аргумент — весь `Cancelled`: причина, описание, признак старта и стек.
Вызов синхронный, поздняя регистрация вызывается сразу. Есть снятие,
повторное снятие безопасно. Ожидающие обработчики идут по снимку; новый
обработчик из вызванного выполняется сразу. Завершение без отмены
освобождает регистрации. Ошибки идут тем же маршрутом, что у
`ctx.onCancel`; future асинхронного обработчика не ожидается.

Уведомление покрывает пометку работающей задачи, снятие до старта и
самоотмену тела. В последнем случае оно идёт после детей, перед уборкой,
и не вызывает внутренние `ctx.onCancel`. При снятии до старта сначала
завершаются внутренние переходы и хуки движка, затем внешний колбэк.

Версия ядра в дереве — 0.2.0: изменение несовместимо с опубликованной
0.1.0. Зависимость `solo` обновлена; локальные оверрайды ядра восстановлены
во всех зависимых пакетах и примерах. Публикации и push не было.

# Независимое ревью

Ревьюер прочитал жизненный цикл ядра и интеграцию с очередью `solo`,
проверил пять сценариев одноразовыми зондами. Одна находка:

## P2: завершённая при применении политики задача занимает ключ

Когда текущая задача занята, поставить `old` в очередь, создать `incoming`
с тем же ключом и зарегистрировать
`old.whenCancelled((_) => incoming.cancel())`. Вызов
`add(incoming, policy: Policy.replace)` синхронно отменяет `incoming`,
затем всё равно вставляет её в очередь: после политики проверяется только
`isClosed`. Следующий `droppable` возвращает завершённую задачу вместо
выполнения новой работы. Проверка `isFinished` в `_pump` приходит поздно.
Аналогичный путь существовал через `onFinish`; новый синхронный API
открывает его обычному потребителю хэндлов.

**Вердикт:** подтверждено собственным падающим тестом; исправлено проверкой
`impl.isFinished` перед вставкой. Тест проверяет и отсутствие завершённой
задачи в очереди, и выполнение следующего `droppable`. Повторный зонд
ревьюера дал `queued=false`, `retry ran=true`, `Done(null)`.
