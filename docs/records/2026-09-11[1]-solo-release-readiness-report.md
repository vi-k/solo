# Область работы

Владелец попросил подготовиться к публикации `solo`. Это подготовка в
дереве, не поручение выполнить связку выпуска. Релизный коммит, тег,
push и `dart pub publish` не выполнялись.

# Правки

Сняты оверрайды опубликованного ядра: удалены
`packages/solo/pubspec_overrides.yaml` и
`packages/solo/example/pubspec_overrides.yaml`. Пакет и его пример
разрешают `async_job` с pub.dev. В `pubspec.lock` обоих источник
`hosted`, версия 0.2.0, sha256 `60c88a81…ac6b`.

`packages/solo/.pubignore` сокращён до одной записи `README.ru.md`:
запись про `example/pubspec_overrides.yaml` описывала уже удалённый
файл и называла ядро прежним именем `jobs`. Теперь файл совпадает с
`.pubignore` уже опубликованного `async_job`.

В `packages/solo/CHANGELOG.md` абзац «The first published release…»
перенесён в начало раздела 0.2.0. Он написан как вступление ко всему
разделу и снимает вопрос о пометках **Breaking** внутри него, но лежал
после шести верхних пунктов, добавленных позже. Из-за этого раздел
открывался указанием мигрировать с версии, которой ни у кого не было:
«Replace `await ctx.run(child).value`…». Проза пунктов не менялась,
переезжал только абзац; перевода у CHANGELOG нет.

# Что осталось владельцу решить

**README зовёт ставить ещё не опубликованный `flutter_solo`.** В разделе
Install стоит `flutter pub add flutter_solo`, а во вступлении ссылка
`https://pub.dev/packages/flutter_solo`; сейчас этот адрес отвечает 404.
Правда станет правдой после выпуска `flutter_solo`, и порядок выпусков
уже выбран: сначала `solo`, потом `flutter_solo`. Пока промежуток не
закрыт, страница `solo` на pub.dev будет предлагать несуществующий
пакет и вести на 404. Либо выпускать оба подряд, либо править README
и перевод до выпуска. Сам текст не трогал: правка зависит от выбора.

**Dev-зависимость `lints` отстаёт.** В дереве `^5.1.1`, разрешима
`6.1.0`. На потребителей не влияет: dev-зависимости не наследуются.
Поднимать перед выпуском не стал — новый набор правил может дать
замечания анализатора, и делать это надо разом во всех пакетах, а не
в одном. Отдельная работа.

# Не выполнялось

Связка выпуска целиком: релизный коммит `Release solo 0.2.0`,
аннотированный тег `solo-v0.2.0`, push и `dart pub publish`. Разрешения
на неё не было; по `AGENTS.md` оно приходит отдельным запросом, который
не содержит ничего, кроме просьбы опубликовать.

`flutter_solo` не готовился: у него и его примера оверрайды на
`solo` и `async_job` остались, его проверки не перезапускались.
Чужая правка `.vscode/launch.json` вне пакета не тронута.
