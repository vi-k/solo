# Вход у `async_job`: README на один-два экрана, дизайн

> **Состояние на 2026-11-04:** дизайн написан, ждёт ревью и слова владельца.
> **Что это:** состав README ядра как входа: что в нём остаётся, что
> добавляется и куда уходят разделы, которые ставят порог входа.
> **Связанные записи:** `2026-10-30-pub-dev-landscape-review.md`,
> `2026-10-17-async-job-project-review.md`.

## Зачем

Пункт 3 первого списка `2026-10-30-pub-dev-landscape-review.md`: короткий вход
на один-два экрана перед нынешними страницами. Ревьюер Opus поставил порогу
входа ядра 4 из 10: «Quick start короткий, но уже вторым экраном идут
ответчики, зона, "наблюдение провала"». Владелец 2026-11-02 отложил пункт,
2026-11-04 взял его в работу: вход для `async_job`, а не для `solo`; одна
короткая страница, на которой `Job`, `ctx.join`, `ctx.abandonable`, `dispose`,
`cancel()` и исход, и только это. На вопрос, где вход живёт, владелец
2026-11-04 ответил «README и есть вход»: читатель pub.dev попадает в README,
и порог стоит в нём самом.

Сейчас в README ядра около 2750 слов. Его Quick start уже показывает `Job`,
`ctx.join`, `dispose`, `cancel()` и `outcome`; нет только `ctx.abandonable`.
Порог ставит то, что идёт за ним: «Why» с флагом и `CancelableOperation`, «A
fuller example» с `discard`, токеном, `uncancellable` и ребёнком, таблица
восемнадцати членов контекста и «Four words» об ответчиках и зоне.

## Цели

- README до «Guides» читается за один-два экрана и вводит ровно шесть вещей:
  `Job`, `ctx.join`, `ctx.abandonable`, `dispose`, `cancel()`, исход.
- Ни одна фраза входа не учит терять провал и не учит закрывать ресурс под
  работой, которая ещё идёт.
- Всё, что уходит из README, остаётся в документации целиком, с тем же кодом,
  выводом и сторожами, и ведёт туда одна ссылка из входа.

## Не цели

- Переписывать уходящие разделы. Они переезжают как есть; правится только то,
  что ломает переезд: ссылки, якоря, первая фраза, если она опиралась
  на соседний раздел README.
- Трогать `solo`, его README и страницы, кроме ссылок на переехавший якорь.
- Новые API, примеры для других пакетов, правки `example/example.dart` сверх
  ссылок в его комментариях.

## Анти-цели

- Вход, который короче, но врёт: `ctx.abandonable` рядом с ресурсом, который
  закрывает `dispose` задачи, или исход через `outcome` в том месте, где
  читатель скопирует его для провала.
- Второй вход рядом с первым: страница «Getting started» поверх README
  повторяла бы его Quick start.

## Состав README

Порядок разделов:

1. **Вступление**: два нынешних абзаца без изменений по смыслу. Первый — что
   пакет делает; второй — `Job` выполняет тело, `done` и `value`, `Job`
   не `Future`, поэтому `await job` ничего не ждёт.
2. **Install**: как сейчас — `dart pub add` и абзац о плагине
   `async_job_lints`.
3. **Quick start**: нынешний блок, его вывод и абзац под ним. Ссылка «in the
   sense of [Four words](#four-words)» ведёт на новое место раздела.
4. **Новый раздел о `ctx.abandonable` и исходе** — сразу за Quick start, один
   блок кода и его вывод. Что он показывает:
   - задача ждёт вызов через `ctx.abandonable`, и `cancel()` возвращается,
     не дожидаясь вызова, — в отличие от `ctx.join` в Quick start, который
     дождался чтения;
   - вызов идёт дальше, и его результат отброшен; вывод это показывает;
   - исход читается `switch` по `await job.done` с тремя случаями — форма
     раздела «A switch over `done`» `doc/outcomes.md`; `done` не бросает
     и замечает провал, `outcome` его не замечает. Вызов под `abandonable`
     не держит ресурса, который закрывает уборка задачи: это запрос, ответ
     которого больше никому не нужен, — так `abandonable` описывает
     `doc/cancellation.md`. Абзац под блоком — две-три фразы: чем `abandonable`
     отличается от `join` и когда какой брать, со ссылкой
     на `doc/cancellation.md`.
5. **Guides**: таблица страниц как сейчас; первой строкой — новая страница
   с уходящими разделами.
6. **Versions** и **solo**: без изменений. Они стоят после «Guides» и порога
   входа не ставят: это обещание выпусков и указатель на соседний пакет, их
   читают, когда уже решили взять пакет.

Цель по объёму — до «Guides» около 600 слов вместе с кодом; нынешний README
до «Guides» — около 2100.

## Куда уходят разделы

Одна новая страница ядра, `packages/async_job/doc/closer-look.md`, «A closer
look». На ней в нынешнем порядке и с нынешними заголовками: «Why», «A fuller
example», «The context at a glance», «Four words». Вступление страницы —
одна-две фразы: README вводит задачу, эта страница — следующий шаг, почему
задача и что ещё умеет контекст. Карты разделов во вступлении нет, решение 107.

Почему одна страница, а не четыре по разделам: каждый раздел — короткий шаг
после входа, и по отдельности они стали бы страницами в один экран, которые
оглавление ставит рядом с «Outcomes» и «Cancellation» как равные. Почему
не в существующие страницы: «Why» и «A fuller example» не принадлежат одной
теме, а таблица контекста и «Four words» сводят несколько страниц сразу.

Решение 77 `docs/settled.md` — «`doc/why.md` не заводится, раздел "Why"
сокращён на месте» — этим пересматривается: по слову владельца «README и есть
вход» «Why» уходит из README вместе с остальными тремя разделами. В пункт
ставится новая дата и новое решение тем же коммитом.

## Что тянет за собой переезд

- **Перевод.** `packages/async_job/README.ru.md` сокращается так же, новая
  страница получает перевод `docs/ru/async_job/closer-look.md`. Сверка —
  `tool/check_translations.py`.
- **Сайт.** Страница встаёт в боковую панель ядра второй, сразу после
  «Overview» (README), в `site/astro.config.mjs`, с русским заголовком.
  Сборка — `tool/build_site.py`, тест тем — `tool/build_site_test.py`.
- **Ссылки на якорь `#the-context-at-a-glance`.** Три: две
  в `packages/solo/doc/reference.md`, одна
  в `packages/async_job_lints/README.md`, и их переводы. Они ведут на новую
  страницу абсолютным адресом GitHub, решение 74. Внутренние ссылки README
  на свои уходящие разделы и ссылки уходящих разделов на `doc/…`
  перестраиваются под новое место; проверка — `tool/check_links.py`.
- **Сторож README.** `packages/async_job/test/readme_recipe_test.dart` читает
  из README блоки «Why» и «A fuller example», вывод примера и таблицу
  контекста, из README и из перевода. Всё это теперь читается с новой страницы
  и её перевода; блок Quick start и новый блок — по-прежнему из README. Новый
  блок исполняется так же, как Quick start: его код стоит между метками в файле
  примера или в тесте, и тест сверяет вывод, который цитирует README, с выводом
  программы. Перевод страницы лежит вне пакета, поэтому тест в архиве ищет его
  так же, как сейчас `README.ru.md`: нет файла — читается только оригинал.
- **Пример.** Комментарии `example/example.dart` и `example/quick_start.dart`,
  которые называют разделы README, называют новое место.
- **Записи о выпуске.** В «Unreleased» `packages/async_job/CHANGELOG.md` и его
  перевода — одна строка в «Documentation»: README сокращён до входа, четыре
  раздела ушли на «A closer look».
- **Проверки формы.** Раздел, переехавший на страницу, открывается тем же кодом
  или таблицей, что и в README, и `tool/check_doc_shape.py` держит его так же.
  Новый раздел README открывается кодом.

## Что решено мной

- Имя и заголовок страницы: `closer-look.md`, «A closer look», по-русски
  «Подробнее». Строчная форма в оглавлении: «A closer look».
- «Versions» и «solo» остаются в README целиком: они после «Guides».
- Новый раздел README называется по тому, что делает читатель, например
  «Walking away from a call»; точное имя — исполнителю, по правилу о том, что
  заголовок называет задачу читателя.
- Пример нового раздела — запрос без ресурса; фейк печатает, когда запрос
  отвечает, чтобы вывод показал, что вызов шёл дальше.

## Что оставлено исполнителю

- Точный код и вывод нового раздела в пределах того, что он обязан показать.
- Формулировки вступления новой страницы и строки в «Guides».
- Где исполняется новый блок: в `example/quick_start.dart` рядом с первым или
  в отдельном файле примера; оба варианта годятся, если тест читает код и вывод
  со страницы.
