# Два правила об исходе `done`: отчёт

## Что сделано

По дизайну `2026-11-09-done-lints-design.md`, одобренному владельцем.

  предупреждения, включены, как только плагин назван; `solo_lints` приносит их

## Замер

Каждый файл анализировался отдельно: прогон `dart analyze` по каталогу
возвращается раньше, чем плагин доложит обо всех файлах, и терял срабатывания.
Плагин — `async_job_lints` из дерева; охват — пять пакетов с примерами и шесть
стендов документации.

Правило 2, `outcome_after_await`:

| Где | Срабатываний | Файлов |
| --- | --- | --- |
| `lib/` всех пакетов, примеры | 0 | 0 |
| Ответы страниц | 4, все настоящие, исправлены | `why.md`, `chains.md` |
| Тесты `async_job` | 14 | 7 |
| Тесты `solo` | 6 | 3 |
| Тесты `flutter_solo` | 2 | 1 |
| Драйверы стендов | 5 | 3 |

В тестах это `await job.done` или `expect(await job.value, …)` после ожидания.
Ответ `why.md` ждал 10 мс до `await job.done`, и задача, упавшая за это время,
отдала бы ошибку в зону.

Правило 1, `discarded_outcome`:

| Где | Срабатываний | Файлов |
| --- | --- | --- |
| Пример `solo`, `bin/main.dart` | 2, исправлены | 1 |
| Код страниц | 3, все в ошибочных попытках | 3 |
| Тесты трёх пакетов | 126 | 31 |
| Драйверы стендов | 20 | 5 |

Попытки — в `time.md` ядра, `cancellation.md` `solo` и `testing.md`
`flutter_solo`. Вторая попытка `time.md`,
`job.done.whenComplete(timer.cancel)`, — ровно дефект правила: страница сама
говорит, что ошибка больше не доходит до зоны.

## Ревью работы

Независимое ревью Opus по диапазону `0c5c542d..194348e8`, против дизайна,
зондами на analyzer 12.1.0 (Dart 3.10) и 14.7.0. Ревьюер подтвердил: оба
правила совпадают с дизайном в остальном, совместимость с analyzer 12.1 (56
тестов правил зелёные на полу), плагин молчит в `lib/` и `example/`, страницы
и переводы верны, числа замера сходятся.

**1. Важно. `discarded_outcome` молчит на колбэке в именованном аргументе.**
Ожидаемый тип колбэка берётся из `correspondingParameter` литерала,
а у литерала в именованном аргументе он `null`.
`refreshNamed(onRefresh: () => load().done)` и блочное
`onRefresh: () { return load().done; }` не дают диагностики, хотя README
и дизайн обещают ловить ровно `onRefresh:`. Так же молчит литерал в переменной
объявленного типа `final Future<void> Function() f = () => load().done;`.

Вердикт: принято, исправлено. Подтверждено падающими тестами до правки.
Параметр ищется по имени в типе вызова (`staticInvokeType` или тип
конструктора) — узел именованного аргумента в analyzer 12 и 14 разный, поэтому
имя берётся по токенам, как в `context.dart`; для переменной берётся её
объявленный тип. Тесты `test_returned_into_a_named_callback`,
`test_returned_from_a_block_into_a_named_callback`,
`test_returned_into_a_named_constructor_argument`,
`test_returned_into_a_typed_variable`.

**2. Важно. Стрелочная async-функция с `await` выбрасывает исход в `void`
молча.** `Future<void> reload() async => await load().done;`
и `refresh(() async => await load().done);` не дают диагностики: `await`
снимается в инструкции, но не в возвращаемом значении.

Вердикт: принято, исправлено: возвращаемое значение тоже снимает `await`. Тесты
`test_awaited_and_returned_into_future_void`,
`test_awaited_and_returned_into_a_callback`,
а `test_awaited_and_returned_as_an_outcome` держит молчание, когда функция
возвращает сам исход. Блочное `return await load().done;` в функции
`Future<void>` не компилируется, теста на него нет.

**3. Мелочь. README правила 2 называет несуществующий `ctx.wait`.**

Вердикт: принято, `wait` убран из README и перевода.

**4. Мелочь. Оба правила ставят диагностику на один `done`.**
`final job = load(); await commit(); await job.done;` без чтения ниже даёт обе.
Совет правила 1 — `value` или `ignoreFailure()` на этой строке — после правки
задевает правило 2.

Вердикт: принято фразой в README правила 2 и в переводе: такую строку называют
оба правила, и ответ — раннее чтение с исходом в деле. Молчание правила 1 там,
где сработает правило 2, не сделано — решение 149 `docs/settled.md`.

**5. Мелочь. Ложное срабатывание на `late`.** У `late final job = load();`
инициализатор выполняется при первом чтении, окна нет.

Вердикт: принято, исправлено: правило пропускает `late`, README говорит
«не `late`». Тест `test_late`.

**6. Мелочь. Тесты правила 2 не держат часть обещанного дизайном.** Нет случаев
на `whenCancelled`, `isCancelled`, `isFinished`, `key`, `describe()`, `level`,
`isChild`, на уход возвратом, элементом коллекции и интерполяцией; удаление
`'whenCancelled'` из списка свидетелей прошло бы набор.

Вердикт: принято. `test_members_that_do_not_observe` перечисляет всех
свидетелей: неизвестный член — уход, и правило замолчало бы, так что пропажа
любого из списка роняет тест; мутация с `'whenCancelled'` его уронила.
Добавлены `test_returned`, `test_collection_element`, `test_interpolated`.
`ctx.run(job)` бывает только в замыкании и держится `test_captured`. R2
(`value..ignore()`) в тесте не собрать: в SDK `analyzer_testing` нет
`Future.ignore`. R9 и S7 — зонды поведения ядра в дизайне; сторона правила
у них — `test_observed_early` и `test_cancel_of_the_same_job`.

**7. Мелочь. Сторож `vs_bloc_rakes_test.dart` из 1036d59f держит фразу о форме
кода, которую тест не проверяет.** Тест проверяет `Cancelled(replaced)`
у первых двух ходов.

Вердикт: принято, сторож держит фразу страницы «the first two moves end
`Cancelled(replaced)`, each replaced by the next».

**8. Мелочь, вне дизайна. Скобки и `unawaited`.** `print(await (job).done)`
правило 2 считает уходом и молчит; `unawaited(load().done)` правило 1 молчит,
и README этой формы не называет.

Вердикт: `unawaited(job.done)` добавлен в список того, что правило 1
не называет. `(job).done` оставлен — решение 150 `docs/settled.md`.
