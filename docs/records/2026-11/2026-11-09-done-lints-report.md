## Ревью работы

Независимое ревью Opus по диапазону `0c5c542d..194348e8`, против дизайна,
зондами на analyzer 12.1.0 (Dart 3.10) и 14.7.0. Ревьюер подтвердил: оба
правила совпадают с дизайном в остальном, совместимость с analyzer 12.1 (56
тестов правил зелёные на полу), плагин молчит в `lib/` и `example/`, страницы
и переводы верны, числа замера сходятся.

**1. Важно. `discarded_outcome` молчит на колбэке в именованном аргументе.**
Ожидаемый тип колбэка берётся из `correspondingParameter` литерала,
а у литерала в именованном аргументе он `null`.
`refreshNamed(onRefresh: () => load().done)` и блочное
`onRefresh: () { return load().done; }` не дают диагностики, хотя README
и дизайн обещают ловить ровно `onRefresh:`. Так же молчит литерал в переменной
объявленного типа `final Future<void> Function() f = () => load().done;`.

Вердикт: принято, исправлено. Подтверждено падающими тестами до правки.
Параметр ищется по имени в типе вызова (`staticInvokeType` или тип
конструктора) — узел именованного аргумента в analyzer 12 и 14 разный, поэтому
имя берётся по токенам, как в `context.dart`; для переменной берётся её
объявленный тип. Тесты `test_returned_into_a_named_callback`,
`test_returned_from_a_block_into_a_named_callback`,
`test_returned_into_a_named_constructor_argument`,
`test_returned_into_a_typed_variable`.

**2. Важно. Стрелочная async-функция с `await` выбрасывает исход в `void`
молча.** `Future<void> reload() async => await load().done;`
и `refresh(() async => await load().done);` не дают диагностики: `await`
снимается в инструкции, но не в возвращаемом значении.

Вердикт: принято, исправлено: возвращаемое значение тоже снимает `await`. Тесты
`test_awaited_and_returned_into_future_void`,
`test_awaited_and_returned_into_a_callback`,
а `test_awaited_and_returned_as_an_outcome` держит молчание, когда функция
возвращает сам исход. Блочное `return await load().done;` в функции
`Future<void>` не компилируется, теста на него нет.

**3. Мелочь. README правила 2 называет несуществующий `ctx.wait`.**

Вердикт: принято, `wait` убран из README и перевода.

**4. Мелочь. Оба правила ставят диагностику на один `done`.**
`final job = load(); await commit(); await job.done;` без чтения ниже даёт обе.
Совет правила 1 — `value` или `ignoreFailure()` на этой строке — после правки
задевает правило 2.

Вердикт: принято фразой в README правила 2 и в переводе: такую строку называют
оба правила, и ответ — раннее чтение с исходом в деле. Молчание правила 1 там,
где сработает правило 2, не сделано — решение 149 `docs/settled.md`.

**5. Мелочь. Ложное срабатывание на `late`.** У `late final job = load();`
инициализатор выполняется при первом чтении, окна нет.

Вердикт: принято, исправлено: правило пропускает `late`, README говорит
«не `late`». Тест `test_late`. Узкое ревью `ffc6b5b6` показало, что пропуск
теряет окно, когда переменную прочитали до ожидания; теперь окно `late`
открывается первым чтением переменной — раздел «Узкое ревью ffc6b5b6», находка
3.

**6. Мелочь. Тесты правила 2 не держат часть обещанного дизайном.** Нет случаев
на `whenCancelled`, `isCancelled`, `isFinished`, `key`, `describe()`, `level`,
`isChild`, на уход возвратом, элементом коллекции и интерполяцией; удаление
`'whenCancelled'` из списка свидетелей прошло бы набор.

Вердикт: принято. `test_members_that_do_not_observe` перечисляет всех
свидетелей: неизвестный член — уход, и правило замолчало бы, так что пропажа

Добавлены `test_returned`, `test_collection_element`, `test_interpolated`.
`ctx.run(job)` бывает только в замыкании и держится `test_captured`. R2

**7. Мелочь. Сторож `vs_bloc_rakes_test.dart` из 1036d59f держит фразу о форме

## Узкое ревью ffc6b5b6

Коммит `ffc6b5b6` с правками по ревью работы — единственный код выпуска
`async_job_lints` 0.2.0, которого не видел независимый ревьюер. По слову
владельца «да, запускай узкое ревью» 2026-11-09 его прочитал Opus в своей
копии: зондами на analyzer 12.1.0 (Dart 3.10.0) и 14.7.0, мутациями, гейтом
на обоих SDK. По отчёту ревьюера все шесть находок ревью работы коммит
закрывает одинаково на обеих версиях, а гейт зелёный на обоих SDK. Каждую
из четырёх находок ниже Claude подтвердил своим зондом. Исправлены все по слову
владельца «да, делай все четыре».

**1. Мелочь. Именованный аргумент в `super(...)`, `this(...)` и `.new(...)`
молчит.** Ветка поиска параметра знает только `InvocationExpression`
и `InstanceCreationExpression`; у вызова конструктора через dot-shorthand
`staticInvokeType` пуст. Позиционный `super(...)` ловится. Предложено:
`ConstructorReferenceNode(:final element) => element?.type`.

Вердикт: принято, исправлено как предложено. Тесты
`test_returned_into_a_named_super_argument`,
`test_returned_into_a_named_redirecting_argument`,
`test_returned_into_a_named_dot_shorthand_argument` падали до правки.

**2. Мелочь, было до коммита. Ожидаемый тип не проходит сквозь скобки, `?:`,
`??`, присваивание, возврат замыкания и элемент коллекции.** Самая частая
форма — `onRefresh: enabled ? () => load().done : null`.

Вердикт: принято. Литерал поднимается сквозь скобки, ветви `?:` и операнды `??`
до места, которое задаёт тип; присваивание `=` даёт тип через `writeType`.
Тесты `test_returned_from_a_branch_of_a_conditional`,
`test_returned_from_an_if_null_operand`, `test_returned_from_parentheses`,
`test_returned_into_an_assigned_variable` падали до правки,
`test_returned_from_a_conditional_into_an_outcome` держит молчание. Возврат
замыкания из функции и элемент коллекции README называет среди того, что
правило не видит, — решение 151 `docs/settled.md`. Второе узкое ревью нашло,
что `??=` молчит; теперь оно даёт тип так же, как `=`, — раздел «Второе узкое
ревью e9050ba1», находка 2.

**3. Мелочь. Пропуск `late` теряет окно.** Если `late`-переменную прочитали
до ожидания, например `job.isRunning`, задача создана до `await`, и окно
такое же, как без `late`.

Вердикт: принято, исправлено как предложено: окно `late`-задачи открывается
первым обращением к переменной, у `Job.deferred` — по-прежнему `start()`.
README больше не говорит «не `late`». Тест `test_late_read_before_the_wait`
падал до правки, `test_late_made_after_the_wait` и `test_late` держат молчание.
Второе узкое ревью показало, что так окно открывается и чтением, которое может
не выполниться, и правило ругает верный код; теперь окно открывает только
чтение, которое выполняется наверняка, — раздел «Второе узкое ревью e9050ba1»,
находка 1.

**4. Мелочь. Без `'cancel'` в списке членов, которые задачу не наблюдают, набор
зелёный.** Утверждение вердикта 6 «пропажа любого из списка роняет тест» для
`cancel` неверно. Запись `'start'` там мёртвая: `start()` разбирается раньше.

Вердикт: принято. Тест `test_cancel_does_not_observe`; `'start'` из списка
убран.

Мутации правок, откат копией: убрана ветка `ConstructorReferenceNode` — красные
три теста находки 1; подъём к месту выключен — красные три теста скобок, `?:`
и `??`; без ветки `?:` — красный её тест; присваивание без `writeType` —
красный его тест; окно `late` не открыто или открыто объявлением — красный

`test_cancel_does_not_observe`. Пол — Dart 3.10.0 с analyzer 12.1.0, прямые

## Второе узкое ревью e9050ba1

Коммит `e9050ba1` с правками по первому узкому ревью — снова код выпуска,
которого не видел независимый ревьюер. По слову владельца «давай узкое ревью»
2026-11-09 его прочитал Opus в своей копии с одним вопросом: где новые ветки
ругают верный код, падают или упускают обещанное README. Зонды — на analyzer
14.7.0 и на полу 12.1.0. Каждую находку Claude подтвердил своим зондом;
исправлены по слову владельца «да, делай все три, вариант (а)».

**1. Важное. `outcome_after_await` ругает верный код с `late`.** Окно
открывается первым чтением переменной в порядке текста, а это чтение может
не выполниться до ожидания: в ветке
`if (fast) { print(job.isRunning); return; }`, в другой ветке `if`/`else`,
в инициализаторе другой `late`-переменной, во втором операнде `&&`. Задача
тогда создаётся у `done`, и предупреждение ложное; до `e9050ba1` `late`
пропускалось, так что это новые срабатывания — ровно на том приёме, ради
которого пишут `late`. Ревьюер предложил открывать окно только чтением, которое
выполняется на каждом пути, или вернуть пропуск.

Вердикт: принято, вариант (а) владельца: окно открывает только чтение, путь
от которого до блока объявления проходит по закрытому списку узлов, которые
вычисляются всегда, — вызов без `?.`, аргумент, скобки, `await`, условие `if`
и `?:`, левый операнд и операнды без короткого замыкания, обычный
инициализатор, присваивание кроме правой части `??=`. Любой другой узел,
вложенный блок, каскад или инициализатор `late` оставляют правило молчать.
README называет, когда правило молчит. Тесты
`test_late_read_in_a_branch_that_returns`,
`test_late_read_in_the_other_branch`,
`test_late_read_in_another_late_initializer`,
`test_late_read_in_a_short_circuit` падали до правки,
`test_late_read_in_a_null_aware_call` держит `?.`;
`test_late_read_in_a_condition`, `test_late_read_in_an_initializer`,
`test_late_read_in_a_named_argument` и `test_late_read_before_the_wait` держат
то, что окно по-прежнему открывается. Довод ревьюера о подсказке не принят:
`done`, прочитанный сразу после первого чтения, задачу раньше не создаёт.

**2. Мелочь. `??=` молчит.** `reload ??= () => load().done` README обещает
словами «assigned to», а правило берёт тип только у `=`.

Вердикт: принято, исправлено как предложено: `??=` даёт тип через `writeType`,
как `=`. Тест `test_returned_into_an_if_null_assignment` падал до правки.

**3. Мелочь, только на полу. `.new(...)` обобщённого класса молчит на analyzer
12.1.0.** `final Box<void> b = .new(make: () => load().done)` ловится на 14.7.0
и молчит на 12.1.0: там параметр конструктора остаётся с `Future<T>`, без
подстановки. Только пропуск, ложного срабатывания так не получить.

Вердикт: не делать — решение 152 `docs/settled.md`. Зонд подтвердил пропуск
на полу; тестом он не стал, потому что на полу набор краснел бы.

Мутации правок, откат копией: без проверки чтения — красные пять тестов находки
1; блок объявления не сверяется — красные обе ветки; без проверки `?.` —
красный её тест; без короткого замыкания — красный
`test_late_read_in_a_short_circuit`; условие `if` не пропускает — красный
`test_late_read_in_a_condition`; именованный аргумент не пропускает — красный
`test_late_read_in_a_named_argument`; инициализатор `late` пропускает — красный
`test_late_read_in_another_late_initializer`; без `??=` — красный
`test_returned_into_an_if_null_assignment`. Пол — Dart 3.10.0 с analyzer
12.1.0: `analyze --fatal-infos` чист, 83 теста обоих правил зелёные. На текущем
SDK `async_job_lints` +197, `solo_lints` +96, `tool/plugin_probe.py` — все
четыре набора `ok`, пример `solo` с плагином без замечаний.
