## H1. Слив, который некому закончить

```dart
if (wasCurrent || _draining) {
  _schedulePump();
}
```

Конец слива живёт внутри `_pump`, а насос будился только окончанием текущей
работы. Очередь пустеет двумя способами: насос забрал последнюю работу или
последнюю работу сняли с очереди. Второй способ не будил ничего,
и `close(mode: drain)` над очередью, где стояла одна ждущая группа, оставался
навсегда: контроллер `isClosed`, `isDraining`, `!isFinished`, future из `close`
не завершается. Во Flutter это `dispose()`, который не возвращается.

`_onJobFinished` теперь планирует насос для любой закончившейся работы, пока
идёт слив. Это дешевле отдельного метода конца слива: насос и так умеет
возвращаться ни с чем, а лишний микротаск во время слива не стоит ничего.

**Что уточнилось в находке.** Условие у дыры строже, чем написано в ревью:
насос, запланированный самим `close`, должен быть уже потрачен. Первая версия
сторожа снимала группу в том же синхронном куске, что и `close`, — и проходила
на сломанном коде, потому что дыру закрывал тот самый запланированный насос.
Зонд это показал прямо:

```text
after cancelAll: queued=0 draining=true closed=false timers=0
after 5s: draining=true closed=false timers=0
```

Строка `after 5s` — со снятой правкой и с `async.flushMicrotasks()` между
`close` и `cancelAll`. Без этого флеша обе строки говорят `draining=false`.

Сторожа в `drain_test.dart`: «a drain ends when its last waiting group is
cancelled» (снимает `cancelAll`) и «a drain ends when the waiting group cancels
itself» (снимает ручка группы). Оба краснеют, если вернуть `if (wasCurrent)`.

## H2. `droppable` отдаёт работу, которая дела уже не сделает

```dart
final current = _current;
return current != null &&
        !current.isCancelled &&
        !current.isFinished &&
        test(current)
    ? current
    : null;
```

`_current` заполнен всё время, пока отменённое тело разматывается, и ещё
дольше: обнуляется он в `_onJobFinished`, а тот зовётся из `finished()` — после
`_correctState()` и всех обработчиков состояния. В обоих окнах `droppable`
находил эту работу, ронял новую как дубликат и отдавал вызывающему ручку,
которая ничего делать не будет.

**Открытый вопрос из находки решён одним правилом на оба.** `lastJobWhere`
защищённый и отдаёт ту же подсказку подклассу; второго метода нет. Подкласс
спрашивает «кто это уже делает», и отменённая работа — не ответ на этот вопрос.

Правило стоит только на текущей работе. Очередная под него не попадает никогда:
`_SoloJob.cancelWith` снимает работу с очереди прежде, чем пометить её
отменённой, так что очередная работа всегда `!isCancelled && !isFinished`.
Первая версия правки проверяла обе ветки, и проверка в ветке очереди оказалась
мёртвой: ни одна мутация её не будила.

Сторожа в `policy_test.dart`: «droppable does not hand back the cancelled
current job» (окно разматывания, закрыто `isCancelled`) и «droppable does not
hand back the job a handler is finishing» (окно обработчиков состояния, закрыто
`isFinished` — исход уже стоит, а работа ещё текущая). Каждая половинка условия
проверена своей мутацией:

```text
H2: drop `!isCancelled`: 1 caught
    droppable does not hand back the cancelled current job
H2: drop `!isFinished`: 1 caught
    droppable does not hand back the job a handler is finishing
```

## H3. Группа подписок, уносящая кадр

```dart
for (final subscription in _subscriptions) {
  try {
    subscription.cancel();
  } on Object catch (error, stackTrace) {
    FlutterError.reportError(...);
  }
}
_subscriptions.clear();
```

Класс написан против утечки: один участник, который не отпускает, не должен
оставить слушателями остальных. Проход и раньше доходил до конца, но первая
ошибка бросалась по его окончании — из `dispose()`, куда этот вызов и ставит
рецепт README. Исключение из `dispose()` обрывает размотку кадра, и соседние
элементы не размонтируются вовсе: их подписки живут дальше, а виджета в дереве
уже нет. Та же утечка, одним виджетом дальше.

Теперь не бросает вовсе: каждый отказ уходит в `FlutterError.reportError`,
первый в том числе. Ловить бросок из `dispose()` некому, а стоит он кадра.

Сторожа в `subscription_test.dart`: прежний «one member that cannot let go does
not keep the others listening» переписан с `throwsStateError` на два отчёта,
и добавлен виджетный «a member that cannot let go does not stop the frame» —
`Column` из трёх виджетов, средний держит группу над отказывающим источником,
дерево снимается целиком:

```text
cancel() throwing again -> 2 caught
    a member that cannot let go does not stop the frame
    one member that cannot let go does not keep the others listening
```

Первый сторож повторяет зонд ревью и ловит именно потерю кадра: без правки
список размонтированных — `[before, listening]`, маркера `after` в нём нет.
