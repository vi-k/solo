# Контракт

Владелец задал каскад `a → b → c`: отмена звена передаётся назад
к незавершённому предшественнику и вперёд к продолжениям. После обсуждения
ожидания фактической работы и уборки поручил реализацию словом «давай».
Остальные решения ниже — конкретизация агентом этого поручения.

```dart
Job<R> then<R>(
  FutureOr<R> Function(JobContext ctx, T value) onValue, {
  JobObserver? observer,
});
```

Метод возвращает новый корневой `Job<R>` ядра. Он ждёт полного завершения
источника и вызывает обработчик только при `Done`, асинхронно даже для
готового источника. Обработчик получает собственный контекст продолжения,
возвращает значение или future. Возвращённый `Job` автоматически не
разворачивается: дочернюю работу запускают через `ctx.run` и ждут `.value`.
`then` не запускает отложенный источник; им по-прежнему владеет вызывающий.
Продолжение само ждёт источник, его нельзя усыновить через `ctx.run`.

Пока продолжение ждёт источник, оно не работает (`isRunning == false`).
Принятая отмена уже видна через `isCancelled` и `whenCancelled`, но исход
появляется только после завершения источника. Такой исход имеет
`started: false`. При отказе источника от отмены продолжение всё равно
ждёт его завершения. Во время обработчика действуют обычные правила `Job`,
включая `uncancellable`, ожидание детей и уборку.

Обратная отмена и отмена вперёд используют `ChainCancelReason` с полем
`cause`, которое сохраняет исходный `Cancelled`. Причина не обозначает
родителя: звенья связаны зависимостью, а не усыновлением. Уже завершённые
звенья не меняются. Повторный сигнал не заменяет первую принятую отмену.
Разветвление не изолировано: отмена одного продолжения может отменить
общий незавершённый источник и его остальные продолжения.

Ожидание направлено только к предшественнику: источник не ждёт продолжение.
Это исключает цикл ожидания при двусторонней передаче сигнала отмены.
`cancel()` последнего звена ждёт завершения предшественников и собственной
работы. Ожидание собственного продолжения из тела источника недопустимо:
оно, как ожидание своего `.done`, создаёт взаимную блокировку.

# Ошибки, ресурсы и надстройки

`Failed` передаётся дальше с той же ошибкой и стеком; обработчик не
вызывается. Передача наблюдает ошибку источника, и ненаблюдённая ошибка
сообщается от последнего звена. Если отменённое продолжение не передаёт
ошибку источника, оно не берёт её наблюдение на себя: самостоятельный
провал неотменяемого источника не должен потеряться.

Продолжение получает собственный необязательный `observer`, как обычный
корневой `Job`. Наблюдатель источника не наследуется: у надстроек он может
быть внутренним адаптером, требующим их собственного жизненного цикла.
Обработчиков восстановления `onError`/`onCancel` пока нет.
Ресурс, закрытый через `onDispose` источника, закрыт до продолжения;
передаваемые ресурсы требуют обычного явного владения и `onDiscard`.

На `SoloJob` доступен тот же метод ядра: результат — обычный `Job`,
контекст — `JobContext`, состояние и слот очереди не наследуются.
Чтобы менять состояние, продолжение вызывает обычный метод контроллера,
который ставит новую задачу в очередь. `close` контроллера управляет его
задачами; уже запущенное продолжение ядра имеет отдельную жизнь.

# Устройство

`job_then.dart` — приватная часть `job_base.dart`, класс `_ThenJob<T, R>`
на основе `JobBase<R>`. Источник сообщает исход и принятую отмену,
продолжение передаёт свою принятую отмену назад. Сигналы обрабатываются
синхронной очередью без рекурсивного роста стека. Ожидание исхода источника
не наблюдает ошибку заранее: наблюдение передаётся вместе с `Failed`.
Отмена до старта откладывает окончательный `finish` до исхода источника.
Счётчик ожидающих продолжений даёт позднему `then` получить провал
в окно наблюдения до отчёта источника о ненаблюдённой ошибке.
После завершения ссылки и регистрации освобождаются.
