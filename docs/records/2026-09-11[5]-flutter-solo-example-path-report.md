# Зачем

После выпуска `flutter_solo` 0.2.0 у его примера оставался оверрайд на
сам `flutter_solo` по пути `../` и запись о нём в `.pubignore`. Оверрайд
существовал потому, что `example/pubspec.yaml` объявлял
`flutter_solo: ^0.2.0`, а такой версии на pub.dev не было.

Снять оверрайд и оставить версию значило увести пример на
опубликованный пакет: проверки примера перестали бы видеть правки
в дереве, и сломанный API заметил бы не разработчик, а пользователь.
Владелец выбрал вариант примера `solo` — путь прямо в `pubspec.yaml`.

# Что сделано

- `example/pubspec.yaml`: `flutter_solo: ^0.2.0` заменён на
  `flutter_solo: path: ../`;
- `example/pubspec_overrides.yaml` удалён;
- `.pubignore` сокращён до одной записи `README.ru.md`.

Теперь все три пакета и оба примера семейства живут без оверрайдов.

# Проверки

`flutter analyze` пакета и примера чистые, `flutter test` — 8 тестов,
`flutter pub publish --dry-run` без предупреждений после коммита.
В `example/pubspec.lock` `flutter_solo` идёт из `path: ".."`,
а `solo` — hosted 0.2.0.

Отдельно проверено, что путь работает у скачавшего пакет. Копия пакета
без `.dart_tool`, `build`, `doc`, `README.ru.md` и `pubspec.lock`
разложена вне репозитория; `flutter pub get` в её `example/` разрешился,
`flutter_solo` взялся по пути `..`, `solo` — с pub.dev, `flutter analyze`
чистый. То есть `example/` внутри архива самодостаточен.
