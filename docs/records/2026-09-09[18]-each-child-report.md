# Реализация

`ctx.each(stream, (child, event) { ... })` возвращает дочерний `Job<void>`.
Отдельная отмена снимает подписку, не помечая родителя. Родитель ждёт
ребёнка даже после возврата тела. Обработчик получает контекст ребёнка;
у `solo` сохраняются `SoloContext<S, W>`, рабочий тип и `keepWhile`.
`canStart` родителя не наследуется. Проверки владения `run` не ослаблены.

Отмена немедленно прекращает доставку событий, но ребёнок ждёт начатый
обработчик перед завершением и уборкой. Сохранён буфер ранних событий
из `onListen`. Future отмены подписки, принадлежащая источнику,
по-прежнему не ожидается. Ошибки идут через тело дочернего `Job`.

`each` перенесён из extension в метод `JobContext`. Защищённая фабрика
`createEachJob` даёт надстройке создать своего ребёнка. Алгоритм подписки
стал приватной частью библиотеки `job_base.dart`. Примеры, dartdoc,
CHANGELOG и оба языка README обновлены вместе.

# Предкоммитное ревью

## P2: ошибка обработчика после отмены нарушает правила дочернего Job

Если отменить ребёнка во время асинхронного обработчика, затем обработчик
завершится ошибкой, ошибка уйдёт в зону при отсутствии observer — даже
после `child.ignore()`. Маршрут:
`thrown → fail → done.future → wait._race → notifyError`. Обычное тело
дочернего `Job` после принятой отмены передаёт такую ошибку только
наблюдателю через `notifyObserver`. Это противоречит согласованным обычным
правилам ошибок ребёнка и инварианту 4 архитектуры.

Воспроизведение: одинаковые действия для `ctx.run(Job.deferred(...))`
и `ctx.each(...)` дают у обоих родителя `Done` и ребёнка `Cancelled`,
но для обычного ребёнка зона пуста, а для `each` содержит позднюю ошибку.
Ошибка ожидаемого обработчика должна проходить через жизненный цикл тела
ребёнка, а не считаться поздней ошибкой брошенного `wait`. Существующие
проверки поздних ошибок используют observer и разницы не замечают.

Вердикт: подтверждено и исправлено. Два регрессионных теста без observer
с обычной и ранней доставкой сначала воспроизвели ошибку. Теперь сигнал
окончания не несёт ошибок: тело сохраняет ошибку, ждёт обработчик
и пробрасывает её с исходным стеком через завершение `Job`. При броске
из самого `listen` сохраняется приоритет этого броска. Оба теста проходят,
повторное независимое ревью и исходный зонд подтвердили исправление.
