## 0.2.0

- Два новых предупреждения о результате задачи, включённые, как только плагин
  назван: `discarded_outcome` сообщает об исходе `done`, которого дождались
  и выбросили, — там ошибка не доходит ни до кого, а `outcome_after_await` —
  о первом чтении результата задачи, стоящем после ожидания, — там ошибка ушла
  в зону раньше чтения. `dart analyze` падает на коде, который раньше проходил,
  поэтому выпуск минорный.
- README отправляет за таблицей контекста в справочник `async_job`, куда
  таблица переехала из его README.

## 0.1.1

- Сообщение `bare_await` и его раздел в README больше не ставят `ctx.join`
  рядом с `ctx.abandonable` и `ctx.pause` как ожидание, которое отмена
  обрывает, оставляя шагам, которые должны дойти до конца, один
  `ctx.uncancellable`. `join` ждёт весь вызов и бросает только после него;
  сообщение и README теперь говорят, для чего каждый из четырёх.

## 0.1.0

- Первый выпуск. Пять правил для кода на async_job — `ctx_in_cleanup`,
  `release_on_the_call`, `catch_without_check`, `sync_fake_async`
  и `bare_await` — и быстрые исправления `release_on_the_call`
  и `catch_without_check` пришли из solo_lints 0.1.4 и ведут себя, как там,
  с двумя отличиями: `bare_await` сообщает об ожидании задачи из собственной
  очереди контроллера solo, которое solo_lints оставляет `await_own_queue`,
  а идентификаторы быстрых исправлений начинаются с `async_job_lints.fix.`,
  а не с `solo_lints.fix.`.
- `package:async_job_lints/plugin_api.dart` регистрирует правила в другом
  плагине — для плагинов анализатора, построенных поверх этого.
- У пакета есть пример: рекордер на async_job с тремя ошибками, строки,
  о которых сообщает плагин, и та же задача исправленной.
