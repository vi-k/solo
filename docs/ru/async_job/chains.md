# Цепочки

Цепочка продолжает задачу её результатом. Здесь приложение загружает число
текстом, разбирает его и сохраняет. `then` возвращает новую задачу. Она
стартует, когда источник кончился успехом вместе с детьми и уборкой, и передаёт
колбэку значение и собственный контекст:

```dart
final loaded = Job<String>((ctx) => ctx.join(loadText));
final parsed = loaded.then<int>((ctx, text) => int.parse(text));
final saved = parsed.then<void>((ctx, number) => ctx.join(
      () => saveNumber(number),
    ));

await saved.value;
```

В блоках вывода на этой странице:

- `loaded:`, `parsed:`, `saved:` исход этого звена;
- `parent:`, `child:` исходы после `tail.cancel()` из раздела
  [«Продолжение ребёнка»](#продолжение-ребёнка).

## Отмена цепочки

Текст ещё загружается, когда пользователь уходит с экрана, и экран отменяет
последнее звено:

```dart
// Пользователь ушёл с экрана, пока текст загружался.
await saved.cancel();
print('loaded: ${loaded.outcome}');
print('parsed: ${parsed.outcome}');
print('saved: ${saved.outcome}');
```

```text
loaded: Cancelled(chain)
parsed: Cancelled(chain)
saved: Cancelled(manual)
```

Отмена идёт по цепочке в обе стороны. Незавершённые звенья перед отменённым она
просит отмениться, а звенья после него отменяет. Каждое звено, до которого она
доходит, получает `ChainCancelReason`, и в его поле `cause` лежит `Cancelled`
звена, от которого она пришла:

| Что отменяете | Просит отмениться, если не кончились | Отменяет, когда отменённое звено примет отмену |
| --- | --- | --- |
| `loaded` | никого | `parsed` и `saved` |
| `parsed` | `loaded` | `saved` |
| `saved` | `loaded` и `parsed` | никого |


Звено, которое отмену отвергает, на себе её и останавливает: отмените `loaded`,
созданную с `cancellable: false`, и `parsed` и `saved` пойдут дальше.
Кончившиеся звенья сохраняют свои исходы. Если на одну задачу навешено
несколько продолжений, отмена одного может отменить общий источник, а с ним
и остальные продолжения.

Продолжение стартует только после того, как кончился источник, поэтому
у работающего звена позади нет ничего незавершённого. Пока работает `parsed`,
`loaded` уже кончилась, и `loaded.cancel()` ничего не делает: `parsed` идёт
дальше, а за ней `saved`. Пока работает `saved`, отмена `loaded` или `parsed`
её не трогает. Чтобы остановить работающее звено, отмените его само или одно
из следующих.

`await saved.cancel()` возвращается, когда кончились незавершённые звенья перед
`saved` вместе с их детьми и уборкой и когда `saved` кончила начатую работу
и уборку. Источник сохраняет свои правила: `cancellable: false` отклоняет
запрос, а `uncancellable` придерживает его. Отменённое продолжение всё равно
ждёт такой источник, а потом кончается, не вызвав колбэк. Пока оно ждёт, у него
`isCancelled`, но ещё не `isFinished`. Его исход содержит `started: false`,
если отмену приняли, пока оно ждало источник.

## Когда звено падает

Упавшее звено передаёт ошибку и стек дальше, не вызывая следующий колбэк.
Провал идёт по цепочке вниз и заканчивает каждое звено после упавшего, поэтому
тот, кто наблюдает последнее звено через `value`, `done` или `ignoreFailure`,
обрабатывает провал из любого места цепочки выше. `JobObserver` последнего
звена слышит его как провал этого звена.

Куда уходит ошибка, зависит от того, что упало:

| Что упало | Куда уходит ошибка |
| --- | --- |
| Тело звена или колбэк продолжения | Вниз по цепочке, к тому, кто наблюдает последнее звено. Если его никто не наблюдает, ошибка уходит в зону, где вызвали последний `then` |
| Источник, который отверг отмену своего продолжения и потом упал | В зону, где создан источник, если источник никто не наблюдает. Отменённое продолжение ошибку не передаёт и поэтому не наблюдает |
| Работа `ctx.unattended` или уборщик, ошибку которых не несёт ни один исход | К наблюдателю звена, где она случилась, а потом, если он не перехватит её в `onUnanswered`, в зону, где звено создано. У продолжения это зона, где вызвали `then` |

## Что возвращает колбэк

Колбэк возвращает значение или future, и продолжение ждёт эту future. Здесь
число сохраняет отдельная задача.

### Первая попытка

```dart
// Первая попытка: продолжение не ждёт задачу.
final stored = parsed.then<void>((ctx, number) {
  final saving = Job<void>((ctx) => ctx.join(() => saveNumber(number)));
  return saving;
});
```

Код компилируется. Этот колбэк отмечает линт `void_checks`, который включает
`package:lints`, но стрелочную форму `(ctx, number) => saving` он не отмечает,
а компилятор не отмечает ни ту ни другую. `stored` не ждёт `saving`. Вот что
происходит:

1. `then` ждёт future, а `Job` — не future. Продолжение берёт `saving` своим
   значением и сразу кончается `Done`.
2. `saving` стартует сама и работает дальше одна, и её никто не ждёт.
3. `saving`, созданная через `Job.deferred`, не стартовала бы никогда, потому
   что её здесь никто не запускает. У продолжения типа `void` ядро это
   проверяет, и `stored` падает с `ArgumentError`. Продолжение более широкого
   типа берёт задачу своим значением: задача может быть тем значением, которое
   оно хочет отдать.

### Задача, которую продолжение запускает своим ребёнком

```dart
final stored = parsed.then<void>((ctx, number) {
  final saving = Job.deferred<void>(
    (ctx) => ctx.join(() => saveNumber(number)),
  );
  return ctx.run(saving);
});
```

`ctx.run` запускает `saving` и возвращает future её значения, и продолжение
ждёт эту future.

## Продолжение — не ребёнок

Каждое продолжение — корневая задача ядра, где бы ни вызвали `then`. Созданное
в теле другой задачи, оно не становится её ребёнком, и эта задача его не ждёт.
У него есть необязательный аргумент `observer`. Ни наблюдателя источника,
ни того, что движок навесил на источник, оно не наследует.

| | Ребёнок | Продолжение |
| --- | --- | --- |
| Создаётся | `Job.deferred` | `then` |
| Стартует | когда родитель запускает его через `ctx.run` | само, когда источник кончился успехом |
| Его ждёт | родитель | никто: это корневая задача |
| `ctx.run` его принимает | да, это `ChildJob` | нет, это простая `Job` |

`then` не запускает свой источник. Цепочка, навешенная на `Job.deferred`, стоит
незапущенной, каждое её звено, пока источник не запустят: вызовом `start()` или
через `ctx.run(source)` в теле, которое берёт его ребёнком.

## Что отдаёт источник

`opened` открывает строки и отдаёт их, а `archived` пишет их в архив:

```dart
final opened = Job<Source>(
  (ctx) => ctx.abandonable(openRows, discard: (rows) => rows.close()),
);
final archived = opened.then<void>((ctx, rows) async {
  ctx.onDispose(rows.close);
  await ctx.join(() => writeArchive([rows]));
});
```

Уборка, которую зарегистрировал источник, к передаче значения уже выполнена:
ресурс, закрытый через `onDispose` источника, в этот момент уже закрыт.
С `discard` всё наоборот: он выполняется, только если значение не дошло
ни до кого. `opened` кончилась `Done`, поэтому её `discard` не выполнялся
и не выполнится. Получателем становится продолжение: `rows` приходит к нему
аргументом, и закрытие оно регистрирует в своём теле, первой строкой.

Один случай остаётся без получателя вовсе. `archived.cancel()`, пока `opened`
ещё открывает, кончает `archived`, ни разу не позвав его колбэк, так что тела,
где можно что-то зарегистрировать, нет. Отмена идёт дальше, к `opened`, и кто
закроет строки, зависит от того, что `opened` с ней сделает:

| Как идёт цепочка | Кто закрывает строки |
| --- | --- |
| `archived` получает строки | `archived`, через `ctx.onDispose` |
| `archived` отменяют, пока `opened` открывает, и `opened` принимает отмену | `opened`, через свой `discard`, когда строки приходят |
| То же, но `opened` её отвергает: `cancellable: false` или кончилась к приходу запроса | Вызывающий, через хэндл: `(await opened.value).close()`, как у [ветки, отвергающей остановку группы](groups.md#что-группа-отдаёт-обратно) |

## Продолжение ребёнка

Родителю нужны строки, а доклад о них может кончиться позже родителя:

```dart
final child = Job.deferred<int>((ctx) => ctx.abandonable(load));
final tail = child.then<void>((ctx, rows) => report(rows));

final parent = Job<void>((ctx) async {
  // Источник остаётся ребёнком: родитель его запускает и дожидается.
  ctx.log(await ctx.run(child));
});

await parent.value; // Done, что бы ни делал tail.
await tail.value; // tail наблюдать вам.
```

Родитель ждёт своих детей, а не то, что на них навешано. Как только
`ctx.run(child)` вернулся и тело закончилось, родитель завершается `Done`, пока
медленное продолжение ещё работает. Что останавливает `tail`, зависит от того,
ждёт ли оно ещё ребёнка:

| Что | Пока `tail` ждёт ребёнка | Пока `tail` работает |
| --- | --- | --- |
| Отмена родителя | Останавливает: родитель отменяет ребёнка, а отмена ребёнка идёт вперёд как `ChainCancelReason` | Не доходит |
| `tail.cancel()` | Останавливает | Останавливает |
| `ctx.onCancel(() => tail.cancel().ignore())` в теле родителя, которое ещё идёт | Останавливает | Останавливает |

В обратную сторону продолжение до источника доходит, пока источник работает.
`tail.cancel()`, пока ребёнок ещё загружает, идёт назад по цепочке, как описано
в разделе [«Отмена цепочки»](#отмена-цепочки), и просит ребёнка отмениться.
`ctx.run(child)` бросает отмену ребёнка в тело родителя, и родитель тоже
кончается `Cancelled`, с `HandlerCancelReason`:

```text
parent: Cancelled(handler: Job(): Cancelled(chain)), child: Cancelled(chain)
```

Ошибка продолжения касается только его самого. Наблюдайте его через `value`,
`done` или `ignoreFailure`; ошибка, которую никто не наблюдал, уйдёт в зону,
где вызвали `then`, уже после того, как родитель закончился. Исход продолжения
возвращается вам, а не родителю.

## Шаги подряд

Задача загружает строки, потом докладывает о них и не должна кончиться раньше
доклада.

### Первая попытка

`then` читается как «а затем», поэтому доклад становится продолжением, и тело
берёт обоих детьми:

```dart
// Первая попытка: ctx.run не принимает продолжение.
final child = Job.deferred<int>((ctx) => ctx.abandonable(load));
final tail = child.then<void>((ctx, rows) => report(rows));

final parent = Job<void>((ctx) async {
  ctx.log(await ctx.run(child));
  await ctx.run(tail);
});
```

Второй `ctx.run` не компилируется:

```text
The argument type 'Job<void>' can't be assigned to the parameter type 'ChildJob<dynamic>'.
```

`ctx.run` принимает `ChildJob`, задачу, которую запускает её родитель,
а продолжение стартует само, когда кончился источник: `then` возвращает простую
`Job`. Длина цепочки ничего не меняет: `child.then(...).then(...)` вешает одно
продолжение на другое, и ни одно звено цепочки не ребёнок.

### Два ребёнка подряд

```dart
final parent = Job<void>((ctx) async {
  final rows =
      await ctx.run(Job.deferred<int>((ctx) => ctx.abandonable(load)));
  await ctx.run(Job.deferred<void>((ctx) => ctx.join(() => report(rows))));
});
```

Последовательность, которая принадлежит операции, строится из детей. Второй
`ctx.run` стартует, когда первый вернул значение, родитель ждёт обоих, и его
отмена доходит до того из них, который сейчас работает. Цепочка нужна для
обратного случая, когда шаг живёт дольше операции или вне операции:
[«Продолжение ребёнка»](#продолжение-ребёнка).

## Источник, который ждёт своё продолжение

Продолжение стартует, когда его источник кончился вместе с уборкой, поэтому
источник, который ждёт собственное продолжение, ждёт вечно:

```dart
late final Job<int> parsed;
final loaded = Job<String>((ctx) async {
  final text = await ctx.join(loadText);
  await parsed.value;
  return text;
});
parsed = loaded.then<int>((ctx, text) => int.parse(text));
```

`parsed` стартует, когда `loaded` кончилась, а `loaded` ждёт `parsed`.
Не кончается ни одна, и `loaded.cancel()` тоже не возвращается. `parsed.done`
на месте `parsed.value` ничего не меняет, как и перенос ожидания в уборку
`loaded`.
