# Цепочки

`then` продолжает работу с результатом предыдущей `Job`. Каждый вызов
возвращает новую `Job` и передаёт колбэку отдельный контекст. Следующий колбэк
запускается после успешного завершения предыдущей `Job`, включая её детей
и уборку:

```dart
final loaded = Job<String>((ctx) => ctx.join(loadText));
final parsed = loaded.then<int>((ctx, text) => int.parse(text));
final saved = parsed.then<void>((ctx, number) => ctx.join(
      () => saveNumber(number),
    ));

await saved.value;
```

Отмена `saved` запрашивает отмену ещё не завершённых `parsed` и `loaded`.
Отмена `parsed` запрашивает отмену незавершённого `loaded` и отменяет `saved`.
Отмена `loaded` передаётся вперёд обоим продолжениям. Переданный запрос
получает `ChainCancelReason`, в поле `cause` которой лежит `Cancelled`
соседнего звена. Завершённые `Job` сохраняют свой исход. Если к одной `Job`
присоединено несколько продолжений, отмена одного может отменить общий источник
и остальные.

Продолжение запускается только после того, как источник закончился, поэтому
у работающего звена позади нет ничего незавершённого. Когда `parsed` работает,
`loaded` уже закончилась, и `loaded.cancel()` ничего не делает: `parsed` идёт
дальше, а за ней `saved`. То же верно на звено ниже: пока работает `saved`,
отмена `loaded` или `parsed` её не трогает. Чтобы остановить работающее звено,
отмените его само или одно из следующих.

`await saved.cancel()` ждёт незавершённых предшественников, их детей и уборку,
а также уже начатую работу и уборку самого `saved`. Источник сохраняет свои
правила отмены: `cancellable: false` отклоняет запрос, а `uncancellable`
придерживает его. Отменённое продолжение всё равно ждёт такой источник, затем
завершается без вызова колбэка. Во время ожидания у него может быть
`isCancelled`, но ещё не `isFinished`; исход содержит `started: false`, если
отмена принята при ожидании источника.

Провал предшественника передаёт ошибку и стек дальше без вызова колбэка.
Наблюдайте продолжение через `value`, `done` или `ignoreFailure`, чтобы
обработать этот провал. Если отменённое продолжение не может передать ошибку
источника, оно её и не наблюдает: например, источник, который отказал отмене,
а затем упал, требует отдельной обработки ошибки.

Колбэк возвращает значение или future, и продолжение ждёт эту future. `Job`
к future не относится. Колбэк, который возвращает задачу,
`then<void>((ctx, number) => saving)`, компилируется, но продолжение `saving`
не ждёт: оно сразу кончается исходом `Done`, а `saving`, которая стартует сама,
работает дальше без него. Отложенную `saving` здесь никто не запускает, поэтому
в таком случае продолжение падает с `ArgumentError`. Эта проверка есть только
у `void`: у более широкого типа задача может быть значением. Продолжение ждёт
ту задачу, которую запускает своим ребёнком:

```dart
final stored = parsed.then<void>((ctx, number) {
  final saving = Job.deferred<void>(
    (ctx) => ctx.join(() => saveNumber(number)),
  );
  return ctx.run(saving);
});
```

`then` не запускает свой источник. Цепочка, навешенная на `Job.deferred`, стоит
незапущенной, каждое её звено, пока источник не запустят: вызовом `start()` или
через `ctx.run(source)` в теле, которое берёт его ребёнком. Само продолжение
ребёнком не берут никогда: оно стартует само, когда кончился источник,
и `ctx.run` его не примет, потому что `then` возвращает простую `Job`,
а не `ChildJob`.

Продолжение стартует, когда его источник кончился вместе с уборкой, поэтому
источник, который ждёт собственное продолжение, ждёт вечно:

```dart
late final Job<int> parsed;
final loaded = Job<String>((ctx) async {
  final text = await ctx.join(loadText);
  await parsed.value;
  return text;
});
parsed = loaded.then<int>((ctx, text) => int.parse(text));
```

`parsed` стартует, когда `loaded` кончилась, а `loaded` ждёт `parsed`.
Не кончается ни одна, и `loaded.cancel()` тоже не возвращается. `parsed.done`
на месте `parsed.value` ничего не меняет, как и перенос ожидания в уборку
`loaded`.

Каждое продолжение является корневой `Job` ядра, где бы ни вызвали `then`:
созданное в теле другой задачи, оно не становится её ребёнком, и эта задача его
не ждёт. У него есть необязательный аргумент `observer`; оно не наследует
ни наблюдателя источника, ни того, что движок навесил на источник.
Зарегистрированная источником уборка уже выполнена к передаче значения: ресурс,
закрытый через `onDispose` источника, в этот момент уже закрыт.

С `discard` источника всё наоборот. Здесь `opened` отдаёт `rows`, которые
открыла, а `archived` их получает:

```dart
final opened = Job<Source>(
  (ctx) => ctx.abandonable(openRows, discard: (rows) => rows.close()),
);
final archived = opened.then<void>((ctx, rows) async {
  ctx.onDispose(rows.close);
  await ctx.join(() => writeArchive([rows]));
});
```

`opened` кончилась `Done`, поэтому её `discard` не выполнялся и не выполнится.
Получателем становится продолжение: `rows` приходит к нему аргументом,
и закрытие оно регистрирует в своём теле, первой строкой.

Один случай остаётся без получателя вовсе. `archived.cancel()`, пока `opened`
ещё открывает, кончает `archived`, ни разу не позвав его колбэк, так что тела,
где можно что-то зарегистрировать, нет. Отмена идёт дальше, к `opened`. Если
`opened` её принимает, её `discard` закрывает `rows`, когда они приходят. Если
`opened` её отвергает (`cancellable: false` или кончилась к приходу запроса),
она всё равно кончается `Done`, с открытыми `rows`. Тогда их закрывает
вызывающий через хэндл, `(await opened.value).close()`, ровно как
у [ветки, отвергающей остановку группы](groups.md#что-группа-отдаёт-обратно).

Наблюдатель последнего звена слышит провал из любого места цепочки выше как
провал этого звена: провал идёт по цепочке вниз и заканчивает каждое следующее
звено. Ошибка без исхода, например провал работы `ctx.unattended` или уборщика,
остаётся на звене, где случилась: она уходит к наблюдателю этого звена и, если
он не перехватит её в `onUnanswered`, в зону, где звено создано; у продолжения
это зона, где вызвали `then`.

## Продолжение ребёнка

Родителю нужны строки, а доклад о них может кончиться позже родителя:

```dart
final child = Job.deferred<int>((ctx) => ctx.abandonable(load));
final tail = child.then<void>((ctx, rows) => report(rows));

final parent = Job<void>((ctx) async {
  // Источник остаётся ребёнком: родитель его запускает и дожидается.
  ctx.log(await ctx.run(child));
});

await parent.value; // Done, что бы ни делал tail.
await tail.value; // tail наблюдать вам.
```

Родитель ждёт своих детей, а не то, что на них навешано. Как только
`ctx.run(child)` вернулся и тело закончилось, родитель завершается `Done`, пока
медленное продолжение ещё работает. Отмена родителя доходит до продолжения,
только пока оно ещё ждёт источник: отмена родителя отменяет ребёнка, а отмена
ребёнка идёт вперёд по цепочке как `ChainCancelReason`. Когда источник кончился
и продолжение заработало, ничто из того, что делает родитель, до него
не доходит. Остановить его может только собственный хэндл продолжения:
`tail.cancel()` или `ctx.onCancel(() => tail.cancel().ignore())` в теле
родителя, пока оно ещё идёт.

В обратную сторону продолжение до источника доходит, пока источник работает.
`tail.cancel()`, пока ребёнок ещё загружает, идёт назад по цепочке, как описано
в начале страницы, и просит ребёнка отмениться. `ctx.run(child)` бросает отмену
ребёнка в тело родителя, и родитель тоже кончается `Cancelled`,
с `HandlerCancelReason`:

```text
parent: Cancelled(handler: Job(): Cancelled(chain)), child: Cancelled(chain)
```

Ошибка продолжения касается только его самого. Наблюдайте его через `value`,
`done` или `ignoreFailure`; ошибка, которую никто не наблюдал, уйдёт в зону,
где вызвали `then`, уже после того, как родитель закончился. Исход продолжения
возвращается вам, а не родителю.

## Шаги подряд

Задача загружает строки, потом докладывает о них и не должна кончиться раньше
доклада.

### Первая попытка

`then` читается как «а затем», поэтому доклад становится продолжением, и тело
берёт обоих детьми:

```dart
// Первая попытка: ctx.run не принимает продолжение.
final child = Job.deferred<int>((ctx) => ctx.abandonable(load));
final tail = child.then<void>((ctx, rows) => report(rows));

final parent = Job<void>((ctx) async {
  ctx.log(await ctx.run(child));
  await ctx.run(tail);
});
```

Второй `ctx.run` не компилируется:

```text
The argument type 'Job<void>' can't be assigned to the parameter type 'ChildJob<dynamic>'.
```

`ctx.run` принимает `ChildJob`, задачу, которую запускает её родитель,
а продолжение стартует само, когда кончился источник: `then` возвращает простую
`Job`. Длина цепочки ничего не меняет: `child.then(...).then(...)` вешает одно
продолжение на другое, и ни одно звено цепочки не ребёнок.

### Два ребёнка подряд

```dart
final parent = Job<void>((ctx) async {
  final rows =
      await ctx.run(Job.deferred<int>((ctx) => ctx.abandonable(load)));
  await ctx.run(Job.deferred<void>((ctx) => ctx.join(() => report(rows))));
});
```

Последовательность, которая принадлежит операции, строится из детей. Второй
`ctx.run` стартует, когда первый вернул значение, родитель ждёт обоих, и его
отмена доходит до того из них, который сейчас работает. Цепочка нужна для
обратного случая, когда шаг живёт дольше операции или вне операции:
[«Продолжение ребёнка»](#продолжение-ребёнка).
