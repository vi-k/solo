# Соглашения

## Язык

- По-русски: `AGENTS.md`, `docs/*.md`, `docs/records/`, общение с владельцем.
- По-английски: `README.md`, `CHANGELOG.md`, сообщения коммитов, тексты
  ошибок и `assert`-сообщений.
- Весь код — по-английски, включая любые комментарии: и dartdoc, и
  внутренние, в `lib/`, `test/`, `example/`, `tool/` и файлах вроде
  `.gitignore`.
- Русские переводы: `README.ru.md` рядом с оригиналом в каждом пакете,
  остальное — в `docs/ru/<пакет>/` (`docs/ru/solo/vs-bloc.md`). Источник
  правды — оригинал; его правка, включая комментарии во фрагментах кода,
  идёт с правкой перевода одним коммитом. Комментарии во фрагментах
  переводятся — `check_translations.py` сверяет код без них. В публикацию
  русский текст не попадает: `README.ru.md` закрыт `.pubignore` пакета,
  прочие переводы лежат вне пакетов, а английские документы на переводы не
  ссылаются.

## Код

- Dart SDK: ограничение в `pubspec.yaml`, локально ставится последний
  stable. Никаких зависимостей на Flutter в ядре.
- Раскладка: монорепозиторий, пакеты в `packages/`. Корень держит только
  `AGENTS.md`, `CLAUDE.md`, `docs/`, `tool/`, `LICENSE` и короткий
  `README.md`.
- Линты: `analysis_options.yaml` в папке каждого пакета (pub.dev анализирует
  пакет без корня репозитория), поверх `package:lints/recommended`
  со строгими режимами `strict-casts`, `strict-inference`, `strict-raw-types`
  и набором стилевых правил: строки до 80 символов, одинарные кавычки,
  завершающие запятые, `prefer_final_locals`, `package_api_docs`. `dart
  analyze` должен быть без предупреждений и info перед коммитом.
- Markdown переносится по ширине **79 символов**, как и весь текст в
  `docs/`. Не переносятся три вещи, которым это не по силам: строка со
  ссылкой, у которой длинный URL, строка таблицы и строка внутри блока
  кода — у кода своя ширина, 80, её держит `dart format`. Проверка —
  `python3 tool/check_line_width.py` из корня.
- Поля класса объявляются выше конструктора: читатель сразу видит, с чем
  класс работает. Правило действует и в коде, и во фрагментах в
  документации, включая фрагменты на чужих пакетах.
- Публичное API документируется dartdoc по-английски: что делает, когда
  бросает, что возвращает при отмене. Примеры в dartdoc — минимальные и
  компилируемые.
- Ошибки: `StateError` на нарушение жизненного цикла (повторный `add`
  задачи), `ArgumentError` на неверный аргумент (политика без ключа).
  Проверки, которые должны работать в release, делаются через `throw`, а не
  `assert`.
- Модификаторы классов. Типы, которые пользователь получает от движка
  (`Job`, `SoloJob`, `JobContext`, `SoloContext`, `SoloQueue`,
  `SoloAccumulator`), —
  `abstract interface class`,
  реализации приватные; реализовать их можно (моки, фейки), наследовать
  нельзя. Иерархии исходов — `sealed class` с `final class` наследниками.
  Причины отмены: открытые абстрактные `CancelReason` и `SoloCancelReason`,
  встроенные наследники `final`; свои причины могут нести любые данные.
  Проверка по типу, `name` — только для журнала, равенства по имени нет.
  Базовые классы, которые пользователь наследует (`SoloBase`, `Solo`,
  `SoloObserver`, `JobObserver`, а также основы ядра `JobBase` и
  `JobContextBase`), — без `base` и `final`: иначе наследники обязаны ставить
  `base`/`final`, а `Mock implements MyController` перестаёт компилироваться.
- Именование: задача — `job`, хэндл — `Job<T>`, контекст — `ctx`, контроллер
  — `Solo<S>`. Фабрики задач внутри контроллера — приватные методы с
  суффиксом `Job`: `_closeCameraJob()`.

## Тесты

- `dart test` из `packages/async_job` и из `packages/solo`. Тесты примера —
  `dart test` из `packages/solo/example/`. Тесты Flutter-пакета —
  `flutter test` из `packages/flutter_solo`.
- Асинхронность тестируется через `FakeAsync` (`package:fake_async`), время
  сдвигается явно. Реального времени в тестах нет.
- Порядок событий проверяется по журналу: тестовый контроллер собирает через
  observer и хуки упорядоченный список строк, тест сравнивает список целиком.
  Это ловит ошибки порядка, которые не ловят проверки конечного состояния.
- Один сценарий — один `test`, имя описывает ситуацию, а не ожидание:
  `'close after 150 ms while child is running'`.
- Тестовая иерархия состояний с объединёнными интерфейсами
  (`InitialAndPreparing`, `PreparingAndWorking`) переиспользуется для всех
  тестов ядра.

## Документация проекта

- `docs/handoff.md` — текущее состояние, всегда актуален.
- `docs/backlog.md` — записи владельца, агент только читает и удаляет
  сделанное.
- `docs/architecture.md` — редко меняющееся устройство.
- `docs/ru/<пакет>/` — русские переводы публичных документов пакета, кроме
  README: тот лежит рядом с оригиналом и закрыт `.pubignore`.
- `docs/records/` — история: `YYYY-MM-DD[N]-name-kind.md` с шапкой о
  состоянии. Правила именования и шапка описаны в `AGENTS.md`.
- Ревью: вердикт в конце каждой находки отдельным абзацем, не больше одного,
  проза не трогается.
- `tool/check_translations.py` — сверка переводов с оригиналами: порядок
  заголовков, число блоков кода и код внутри блоков без комментариев.
  Запускать из корня после любой правки публичного документа; список пар
  задан в самом скрипте, в `PAIRS`: README трёх пакетов и страницы
  `doc/` у `solo` и `async_job`.
- `tool/check_doc_shape.py` — правило «секция начинается с кода»: после
  заголовка в пределах десяти строк прозы должен быть блок кода или
  таблица. Освобождены заголовок страницы, контейнерный раздел (следом
  идёт более глубокий заголовок) и раздел короче десяти строк — это
  указатель, а не объяснение. Проверяется только английская сторона:
  перевод повторяет форму оригинала, и за этим следит
  `check_translations.py`. Устройство публичных документов — в
  `2026-09-11[16]-docs-structure-design.md`.
- `tool/build_site.py` — собирает страницы сайта из README и `doc/`
  пакетов, а русские — из `README.ru.md` и `docs/ru/<пакет>/`,
  в `site/src/content/docs/`. Эти страницы генерируемые и
  не под гитом: источник правды — сами пакеты. Скрипт снимает заголовок
  `#` в frontmatter, который нужен Starlight, и переписывает ссылки между
  файлами в ссылки между страницами. Настройки — `site/site.json`,
  их читают и скрипт, и конфиг Astro. Подробности — `site/README.md`.
- `tool/doc_snippets.py` — стенды для фрагментов `doc/vs-bloc.md`: режет
  код прямо из markdown и собирает запускаемые файлы против bloc и против
  локального `solo`. Запускать после любой правки фрагментов или трасс в
  этом документе.

## Git

- Ветка `main`, без PR. Мерж прямо в `main`.
- Conventional Commits, по-английски: `feat:`, `fix:`, `docs:`, `test:`,
  `refactor:`, `chore:`, `build:`. Область в скобках по желанию:
  `feat(queue): ...`.
- Один коммит — одна логическая правка вместе с её тестами и документами.
- Чужие правки в дереве не коммитить. Файлы вроде `.DS_Store` игнорируются
  через `.gitignore`.
- Публикация на pub.dev — только по правилам из `AGENTS.md`.
