# Соглашения

## Язык

- По-русски: `AGENTS.md`, `docs/*.md`, `docs/records/`, общение с владельцем.
- По-английски: `README.md`, `CHANGELOG.md`, сообщения коммитов, тексты ошибок
  и `assert`-сообщений.
- Весь код — по-английски, включая любые комментарии: и dartdoc, и внутренние,
  в `lib/`, `test/`, `example/`, `tool/` и файлах вроде `.gitignore`.
- Русские переводы: `README.ru.md` рядом с оригиналом в каждом пакете,
  остальное — в `docs/ru/<пакет>/` (`docs/ru/solo/vs-bloc.md`), и перевод
  `CHANGELOG.md` пакета там же под своим именем. Источник правды — оригинал;
  его правка, включая комментарии во фрагментах кода, идёт с правкой перевода
  одним коммитом. Комментарии во фрагментах переводятся —
  `check_translations.py` сверяет код без них. В публикацию русский текст
  не попадает: `README.ru.md` закрыт `.pubignore` пакета, прочие переводы лежат
  вне пакетов, а английские документы на переводы не ссылаются.
- Имя из кода в русском тексте остаётся как в коде, а род берёт от того слова,
  каким его зовут вслух: `future` — женского рода, «ошибка этой future»,
  «`Future`, которая завершается», а не «этого future». Само слово «фьюча»
  в документах не пишется. `Job` вслух зовут «джоба», и она тоже женского рода:
  «`Job` приняла отмену», «дочерняя `Job<void>`, которой принадлежит подписка».
  Слово «джоба» в документах тоже не пишется: в рассказе о работе стоит
  «задача», а `Job` — там, где речь о классе.
- `leaf` о классе внизу цепочки наследования по-русски не «лист»: в переводе
  называется сам предмет, «контроллер приложения, который наследуется от базы»,
  дальше «контроллер приложения» или имя класса из примера. «Лист» о классе
  читателю непонятен.
- В переводе `CHANGELOG.md` `Unreleased` — «Не выпущено», `Breaking:` —
  «Ломающее:», а migration — «миграция», а не «переход»: «переход» в переводах
  занят под `SoloTransition`. Список изменений другого пакета назван «список
  изменений `async_job`» и связан относительной ссылкой,
  `../async_job/CHANGELOG.md`. Имя раздела README, которое оригинал пишет
  код-спаном (`Quick start`), в переводе стоит русским заголовком в кавычках.
  В архив pub.dev перевод не попадает, как и `README.ru.md`, а на сайте он
  есть: список изменений пакета — страница сайта на обоих языках.

## Код

- Dart SDK: ограничение в `pubspec.yaml`, локально ставится последний stable.
  Никаких зависимостей на Flutter в ядре.
- Раскладка: монорепозиторий, пакеты в `packages/`. Корень держит только
  `AGENTS.md`, `CLAUDE.md`, `docs/`, `tool/`, `LICENSE` и короткий `README.md`.
- Линты: `analysis_options.yaml` в папке каждого пакета (pub.dev анализирует
  пакет без корня репозитория), поверх `package:lints/recommended` со строгими
  режимами `strict-casts`, `strict-inference`, `strict-raw-types` и набором
  стилевых правил: строки до 80 символов, одинарные кавычки, завершающие
  запятые, `prefer_final_locals`, `package_api_docs`. `dart analyze` должен
  быть без предупреждений и info перед коммитом. Гейт гоняет его
  с `--fatal-infos`: без флага на info выход нулевой. `flutter analyze`
  краснеет на info и без флага.
- Примеры `solo` и `flutter_solo` подключают плагин `solo_lints` с pub.dev
  в своём `analysis_options.yaml`, с предупреждениями и всеми четырьмя линтами:
  пример показывает код, который правила пропускают. Сам плагин
  в `pubspec.yaml` не стоит, его скачивает сервер анализа. `flutter analyze`
  начиная с Flutter 3.44 диагностик плагина не показывает, поэтому пример
  `flutter_solo` гейт проверяет ещё и `dart analyze --fatal-infos`. Сами пакеты
  плагин не подключают: в их тестах голые ожидания стоят нарочно, замер —
  `2026-10-29-bare-await-design.md`.
- README `async_job`, `solo` и `flutter_solo` называют плагин в разделе
  «Install» блоком `yaml` с версией, и переводы тоже. У `solo` и `flutter_solo`
  версию блока сторож README сверяет с `analysis_options.yaml` их примера,
  у `async_job` сверять не с чем: сторож держит только форму блока. Поэтому
  выпуск `solo_lints` с новой минорной версией правит версию в примерах, в трёх
  README и их переводах одним коммитом.
- Markdown переносится по ширине **79 символов**, как и весь текст в `docs/`.
  Не переносится то, чему это не по силам: строка, переполненная одним
  неразрывным словом — длинным URL, ссылкой вида `[текст](адрес)` или
  код-спаном, — строка таблицы, заголовок и строка внутри блока кода: у кода
  своя ширина, 80, её держит `dart format`. Неразрывное слово здесь то же, что
  у `reflow.py`, иначе заливка и проверка расходятся. Две пустые строки подряд
  вне блока кода — тоже ошибка: на сайте они сливаются в одну, и заметить их
  можно только в исходнике. Проверка того и другого —
  `python3 tool/check_line_width.py` из корня, сторож —
  `tool/check_line_width_test.py`.
- Поля класса объявляются выше конструктора: читатель сразу видит, с чем класс
  работает. Правило действует и в коде, и во фрагментах в документации, включая
  фрагменты на чужих пакетах.
- Публичное API документируется dartdoc по-английски: что делает, когда
  бросает, что возвращает при отмене. Примеры в dartdoc — минимальные
  и компилируемые.
- Ошибки: `StateError` на нарушение жизненного цикла (повторный `enqueueJob`
  задачи), `ArgumentError` на неверный аргумент (политика без ключа). Проверки,
  которые должны работать в release, делаются через `throw`, а не `assert`.
- Модификаторы классов. Типы, которые пользователь получает от движка (`Job`,
  `SoloJob`, `JobContext`, `SoloContext`, `SoloQueue`, `SoloAccumulator`), —
  `abstract interface class`, реализации приватные; реализовать их можно (моки,
  фейки), наследовать нельзя. Иерархии исходов — `sealed class` с `final class`
  наследниками. Причины отмены: открытые абстрактные `CancelReason`
  и `SoloCancelReason`, встроенные наследники `final`; свои причины могут нести
  любые данные. Проверка по типу, `name` — только для журнала, равенства
  по имени нет. Базовые классы и миксины, которые пользователь наследует или
  подмешивает (`Solo`, `SoloStream`, `SoloListenable`, `SoloObserver`,
  `JobObserver`, а также основы ядра `JobBase` и `JobContextBase`), — без
  `base` и `final`: иначе наследники обязаны ставить `base`/`final`,
  а `Mock implements MyController` перестаёт компилироваться.
- Именование: задача — `job`, хэндл — `Job<T>`, контекст — `ctx`, контроллер —
  `Solo<S>`. Фабрики задач внутри контроллера — приватные методы с суффиксом
  `Job`: `_closeCameraJob()`.

## Тесты

- `dart test` из `packages/async_job`, из `packages/solo`
  и из `packages/solo_lints`. Тесты примера — `dart test`
  из `packages/solo/example/`. Тесты Flutter-пакета — `flutter test`
  из `packages/flutter_solo`, его примера — `flutter test`
  из `packages/flutter_solo/example/`.
- Асинхронность тестируется через `FakeAsync` (`package:fake_async`), время
  сдвигается явно. Исключение — тесты `async_job` на настоящих миллисекундах:
  они остаются по решению 82 из `docs/settled.md` и переходят на `fakeAsync`
  по мере правки там, где важен порядок.
- Порядок событий проверяется по журналу: тестовый контроллер собирает через
  observer и хуки упорядоченный список строк, тест сравнивает список целиком.
  Это ловит ошибки порядка, которые не ловят проверки конечного состояния.
- Один сценарий — один `test`, имя описывает ситуацию, а не ожидание:
  `'close after 150 ms while child is running'`.
- Тестовая иерархия состояний с объединёнными интерфейсами
  (`InitialAndPreparing`, `PreparingAndWorking`) переиспользуется для всех
  тестов `solo`.

## Документация проекта

- `docs/handoff.md` — текущее состояние, всегда актуален.
- `docs/backlog.md` — список владельца: агент читает его, удаляет сделанное
  и пишет туда только с согласия владельца.
- `docs/architecture.md` — редко меняющееся устройство.
- `docs/settled.md` — решения «оставить» и «не делать», которые ревьюер без них
  поднял бы снова; бриф полного ревью велит его прочитать.
- `docs/ru/<пакет>/` — русские переводы публичных документов пакета, страниц
  `doc/` и `CHANGELOG.md`, кроме README: тот лежит рядом с оригиналом и закрыт
  `.pubignore`.
- Запись `CHANGELOG.md` — одна фраза о том, что изменилось: «`ctx.wait` is
  renamed to `ctx.abandonable`.» Остальное читатель выводит из кода. Вторая
  фраза стоит только там, где без неё изменение не увидеть или не пережить: код
  собирается, а ведёт себя иначе, или замена не сводится к переименованию.
  Миграцию из одного переименования не пишут, и метки `Migrating.` в записях
  нет. Зачем так сделано, как было раньше и как это устроено, в список не идёт:
  это дело страниц `doc/`, и запись ведёт в нужный раздел ссылкой «See …».
  Исправление того, чего в прошлом выпуске не было, в список не попадает:
  читатель обновляется с выпуска, а не с дерева. Пакет не пересказывает
  изменения пакета под собой: одна фраза в начале раздела ведёт в его список,
  а строкой повторены только переименования, которые заденут код любого
  пользователя. Пункты списка стоят вплотную, без пустых строк. Разделы
  выпущенных версий остаются как выпущены.
- `docs/records/` — история: каталог на месяц (`2026-09/`), в нём файлы
  `YYYY-MM-DD-name-kind.md` с шапкой о состоянии. Правила именования и шапка
  описаны в `AGENTS.md`.
- Ревью: вердикт в конце каждой находки отдельным абзацем, не больше одного,
  проза не трогается.
- `tool/check_translations.py` — сверка переводов с оригиналами: порядок
  заголовков, число блоков кода, код внутри блоков без комментариев и форма
  прозы вокруг них — под каждым заголовком столько же абзацев, пунктов списка
  и строк таблицы, сколько в оригинале, и на тех же местах. Он же следит, чтобы
  тире в переводе было длинным: тире ставится по правилам пунктуации, в прозе
  и в комментариях фрагментов, а скрипт краснит на коротком тире вне диапазона
  чисел и на дефисе между пробелами в прозе. Запускать из корня после любой
  правки публичного документа; список пар задан в самом скрипте, в `PAIRS`:
  README и `CHANGELOG.md` четырёх пакетов и страницы `doc/` трёх, у которых они
  есть.
- `tool/check_doc_shape.py` — правило «секция начинается с кода»: после
  заголовка в пределах десяти строк прозы должен быть блок кода или таблица.
  Освобождены заголовок страницы, контейнерный раздел (следом идёт более
  глубокий заголовок) и раздел короче десяти строк — это указатель,
  а не объяснение. Проверяется только английская сторона: перевод повторяет
  форму оригинала, и за этим следит `check_translations.py`. Устройство
  публичных документов — в `2026-09-11[16]-docs-structure-design.md`. Второе
  правило того же скрипта — пометка попытки: первый блок `dart` под заголовком
  `The first attempt` открывается строкой `// The first attempt: ` и тем, что
  в этом коде ломается, а под `Первая попытка` — строкой `// Первая попытка: `.
  Код попытки неверен нарочно, и читатель, попавший на блок из поиска или
  по ссылке, узнаёт это до кода, а не после. Это правило проверяется на обеих
  сторонах: `check_translations.py` сравнивает код без комментариев. Тесты
  страниц (`page_code.dart`) пометку не видят, как не видят и `// ignore:`
  в тесте, а стенды по документам адресуют блок без объявленного имени
  по первой строке, то есть по пометке.
- `tool/check_dartdoc.py` — форма публичного dartdoc четырёх пакетов, решение
  103 из `docs/settled.md`: первый абзац — одна фраза, абзац прозы не длиннее
  десяти строк, весь блок вместе с кодом — не длиннее тридцати. Публичным
  считается блок `///` в нулевой колонке или на два пробела внутри объявления
  верхнего уровня, если ни у члена, ни у объявления имя не начинается с `_`;
  `example/` и `test/` не проверяются. Пороги — `PARAGRAPH` и `BLOCK` в самом
  скрипте, сторож — `tool/check_dartdoc_test.py`. Без порогов длину не держит
  ничто.
- `tool/check_page_code.py` — четыре копии `test/support/page_code.dart`
  (`async_job`, `solo`, пример `solo`, `flutter_solo`) совпадают с первой байт
  в байт, кроме шапки: у каждой копии свой комментарий, называющий остальные.
  Пакеты не делят тестовый код, и правка, дошедшая до трёх копий, оставила бы
  четвёртый пакет сверять страницы по старому правилу, зелёным.
- Страница частых ошибок `solo`, `doc/mistakes.md`, показывает в каждом разделе
  сперва неверный код, потом верный. Над неверным блоком строка «Don't do
  this:», и блок открывается строкой `// Wrong: ` и тем, что в этом коде
  ломается; над верным — строка «Do this:». В переводе «Так не делайте:»,
  `// Неверно: ` и «Делайте так:». Неверный блок дословно цитирует попытку
  из раздела, куда ведёт первая ссылка раздела, верный — ответ оттуда же. Пар
  в разделе бывает и больше одной: первый показывает ожидание и в теле,
  и в уборке, обе пары из одной попытки и одного ответа. Держит это
  `mistakes_page_test.dart`, метки и пометку — на обеих сторонах; число пар
  каждого раздела записано в нём, и пары должны стоять в том же порядке, что их
  отрезки в попытке и в ответе. Без комментариев неверный блок не может быть
  отрезком ответа, а верный — отрезком попытки: комментарии у попытки и ответа
  свои, и блок, потерявший саму правку, иначе отличался бы от другой стороны
  одним комментарием. `page_code.dart` пометку `// Wrong:` не знает, её снимает
  сам сторож; он же убирает из блока пустые строки, чтобы `page_code.dart`
  искал блок целиком, одним отрезком строк, а не по кускам.
- Ссылка в публичном документе полная: ведёт туда, о чём говорит фраза, —
  в раздел по якорю, а на страницу целиком, только когда речь о всей
  странице, — и называет это место заголовком, как он написан, а не урезанным
  именем страницы. Раздел другой страницы назван вместе со страницей: «раздел
  `[«Почему задачу отменили»](outcomes.md#почему-задачу-отменили)` страницы
  об исходах». По ссылке на страницу целиком нужное место приходится искать
  на всей странице. Английская страница ссылается на другой пакет адресом
  на GitHub, потому что pub.dev показывает пакет без соседей; русская —
  относительной ссылкой на русскую страницу, `../async_job/cleanup.md`.
- Ссылки между пакетами идут вниз, по направлению зависимостей: `solo` построен
  на `async_job`, `flutter_solo` — на `solo`. Страница `doc/` объясняет свой
  пакет читателю, у которого пакета над ним может не быть вовсе, поэтому
  в документы пакета над собой она не ведёт. Назвать его примером можно —
  «`solo`, построенный на этом ядре, …», — а объяснение своего страница держит
  у себя. README — лицо пакета и знакомит с семейством: он советует пакет над
  собой тому, кому тот нужен, и может вести в его README, как README `solo`
  ведёт к `flutter_solo` за `SoloSelector`.
- `tool/check_links.py` — ссылки ведут туда, где что-то есть: файл существует,
  а якорь совпадает с заголовком целевой страницы. Якорь слаггируется как
  на GitHub, повторяющийся заголовок получает хвост `-1`, `-2`. Внешние ссылки
  и ссылки внутри блоков кода не проверяются, `docs/records/` — тоже. Ссылка
  на сам репозиторий на GitHub (`https://github.com/vi-k/solo/blob/main/…`)
  не внешняя, а абсолютная, и проверяется как относительная: файл и раздел
  за ней лежат в этом дереве. Ещё он ловит страницу `doc/` или её перевод,
  которая ведёт в документ пакета над своим; какой пакет над каким, скрипт
  читает из `dependencies` в `pubspec.yaml`, README не проверяет. Сторож —
  `tool/check_links_test.py`, шаг в задании `docs` гейта.
- `tool/build_site.py` — собирает страницы сайта из README, `CHANGELOG.md`
  и `doc/` пакетов, а русские — из `README.ru.md` и `docs/ru/<пакет>/`,
  в `site/src/content/docs/`. Список изменений — страница `<пакет>/changelog/`
  на обоих языках и последний пункт своей группы в боковом меню. Заголовка `#`
  у него нет, поэтому имя страницы, «Changelog» и «Список изменений», даёт
  скрипт; ссылка на `CHANGELOG.md`, относительная или адресом на GitHub, ведёт
  на эту страницу. Эти страницы генерируемые и не под гитом: источник правды —
  сами пакеты. Скрипт снимает заголовок `#` в frontmatter, который нужен
  Starlight, и переписывает ссылки между файлами в ссылки между страницами.
  Относительная ссылка читается от своего файла, как её читает GitHub, а адрес
  репозитория на GitHub становится страницей сайта вместе с якорем. Абзац
  прозы, который ссылается только на ту самую страницу, где стоит, — «Also on
  the documentation site» у README — на сайт не попадает. Сторож —
  `tool/build_site_test.py`, шаг в задании `docs` гейта. Настройки —
  `site/site.json`, их читают и скрипт, и конфиг Astro. Подробности —
  `site/README.md`.
- `tool/archive_floor.py` — гейт, повторённый из архивов и на полу: `stage`
  раскладывает то, что загрузил бы `dart pub publish`, `run` прогоняет
  раскладку на SDK из PATH и требует, чтобы это был пол из `pubspec.yaml`.
  Задание `floor` гейта; порядок и границы — в разделе «Проверки» `AGENTS.md`.
  Сторож разбора — `tool/archive_floor_test.py`, шаг в задании `docs`.
  Запускать перед выпуском и после правки зависимостей или пола.
- `tool/doc_snippets.py` — стенды для фрагментов `doc/vs-bloc.md`: режет код
  прямо из markdown и собирает запускаемые файлы против bloc и против
  локального `solo`. Запускать после любой правки фрагментов или трасс в этом
  документе и в его переводе. Драйверы идут на виртуальном времени: `main`
  каждому даёт сам скрипт, он прогоняет сценарий драйвера под `FakeAsync`.
  Процитированное в прозе держит список `QUOTED`: сборка падает, если такого
  код-спана нет на странице или в переводе, а драйвер — если его прогон этого
  не напечатал. Число, названное в прозе словами, держит список `SAID` вместе
  со сторожем драйвера. Блок страницы, который не взял ни один драйвер, тоже
  роняет сборку.
- `tool/flutter_snippets.py` — стенд для README пакета `flutter_solo` и его
  `packages/flutter_solo/doc/mixins.md`
  и `packages/flutter_solo/doc/testing.md`, заодно и для быстрого старта README
  `solo`: собирает их фрагменты в виджетные тесты, задание `flutter` гейта.
  Запускать после любой правки кода в этих документах. Блок README
  `flutter_solo`, `mixins.md` или `testing.md`, который не взял ни один
  драйвер, роняет сборку; из README `solo` стенд берёт только два блока
  быстрого старта. Импортов сверх показанных на странице драйвер README
  не добавляет, кроме `flutter_test`.

## Git

- Ветка `main`, без PR. Мерж прямо в `main`.
- Conventional Commits, по-английски: `feat:`, `fix:`, `docs:`, `test:`,
  `refactor:`, `chore:`, `build:`. Область в скобках по желанию:
  `feat(queue): ...`.
- Один коммит — одна логическая правка вместе с её тестами и документами.
- Чужие правки в дереве не коммитить. Файлы вроде `.DS_Store` игнорируются
  через `.gitignore`.
- Публикация на pub.dev — только по правилам из `AGENTS.md`.
