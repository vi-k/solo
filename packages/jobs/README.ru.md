# jobs

Отменяемая `Future`: задача с исходом, детьми, кооперативной отменой и
семьёй ожидания. Чистый Dart, из зависимостей только `meta`.

## Зачем

`Future` нельзя отменить. Обычные ответы — флаг, который смотрит тело,
`CancelableOperation`, токен, переданный руками, — оставляют открытыми три
вопроса: чем задача кончилась, кто её ждёт и кто узнает об ошибке, на
которую никто не посмотрел.

Задача отвечает на все три. Она кончается исходом `Outcome`: `Done`,
`Failed` или `Cancelled` с причиной. Она умеет запускать детей и не
считается законченной, пока не закончены они. А `Failed`, который никто не
наблюдал, уходит в зону создания задачи — ровно так Dart поступает с
необработанной ошибкой `Future`.

Отмена кооперативная, и тело не делает `await` само по себе: каждый вызов
идёт через контекст, и выбранный член говорит, что отмена сделает с этим
вызовом.

## Установка

```sh
dart pub add jobs
```

## Быстрый старт

```dart
import 'package:jobs/jobs.dart';

final job = Job<Database>(
  ifCancelled: (database) => database.close(),
  (ctx) async {
    final database = await ctx.join(
      Database.open,
      ifCancelled: (database) => database.close(),
    );
    await ctx.wait(database.migrate);
    await ctx.uncancellable(database.markReady);

    return database;
  },
);

job.cancel().ignore();

final outcome = await job.done;
```

Тело стартует на следующей микротаске, а не внутри конструктора: вызывающий
сначала получает хэндл и может на него подписаться — или отменить задачу
до того, как тело вообще начнётся.

## Исходы

`Outcome<T>` — sealed, поэтому `switch` по трём его случаям исчерпывающий:

```dart
final message = switch (await job.done) {
  Done(:final value) => 'done $value',
  Failed(:final error) => 'failed $error',
  Cancelled(:final reason) => 'cancelled $reason',
};
```

`Cancelled` несёт `reason`, флаг `started`, необязательное `description` и
стектрейс самой отмены. Причина — это `CancelReason`, здесь их три:
`manual`, `parent` и `handler`. Это открытый класс, а не enum: движок,
построенный поверх этого, объявляет свои причины, а равны они по имени.

`job.done` завершается исходом и никогда не бросает; `job.value`
завершается значением или бросает; `job.whenCancelled` завершается в
момент, когда задача отмечена отменённой, ещё до конца тела;
`job.cancel()` отменяет и ждёт, пока задача действительно завершится;
`job.ignore()` говорит, что на исход никто смотреть не будет.

## Отмена

`cancel()` помечает задачу; остановиться — дело тела. Тело не делает
`await` само по себе, и выбранный член говорит, что отмена сделает с этим
вызовом:

- `ctx.wait(action)` прекращает ожидание, но не работу. Действие
  доработает, его результат выбрасывается — или уходит в `ifCancelled`.
- `ctx.join(action)` дожидается всего действия и сдаётся после него:
  команду устройству, уже ушедшую в провод, не бросают на полпути.
- `ctx.uncancellable(action)` отказывает отмене на время вызова. Отказ
  окончателен, а не отложен.
- `ctx.onCancel(callback)` срабатывает в момент пометки, до того как тело
  узнает об отмене: так отмена доходит до того, кто умеет остановиться
  по-настоящему, — токена, обрыва запроса, подписки.
- `ctx.check()` сдаётся там, где обёртывать нечего.

Задача, созданная с `cancellable: false`, отказывает всякой отмене, которой
может отказать; собственные правила — те, что добавит движок сверху, —
действуют всё равно.

```dart
final job = Job<void>((ctx) async {
  final token = CancelToken();
  ctx.onCancel(token.cancel);
  await ctx.join(() => device.seek(position, cancelToken: token));
});
```

## Дети

`ctx.run(child)` запускает ребёнка прямо сейчас, в обход любой очереди,
которую заведёт движок сверху. Родитель не закончен, пока не закончены
дети; отменённый родитель роняет их каскадом, а неотменяемый ребёнок
каскаду отказывает.

```dart
final parent = Job<void>((ctx) async {
  final child = ctx.run(Job.deferred<int>((ctx) => ctx.wait(load)));
  final rows = await child.value;
  ctx.log('$rows rows');
});
```

Ребёнок наследует наблюдателя родителя, если ему не дали своего, а отмена
ребёнка, всплывшая через `child.value`, помечает исход родителя как
`handler` и называет ребёнка.

## Поздние значения

Между `return` тела и исходом задача ещё жива — она ждёт детей, — и
пришедшая туда отмена побеждает. Значение, которое тело посчитало, было бы
выброшено, поэтому его забирает `ifCancelled` самой задачи:

```dart
final job = Job<Database>(
  ifCancelled: (database) => database.close(),
  (ctx) async => Database.open(),
);
```

Исходом всё равно будет отмена. Диспозер работает после детей и до исхода,
и движок его дожидается. Работает он вне тела — ни `onCancel`, ни
`uncancellable` до него не дотягиваются, — поэтому он должен быть коротким
и безусловным.

## Наблюдатель

`JobObserver` — сквозной канал одной задачи: `onStart`, `onFinish`,
`onError`, `onLog`. Передаётся при создании; ребёнок без своего наследует
родительского. Хук, который бросил, отдаёт ошибку текущей зоне и больше
ничего не меняет.

```dart
final class Log implements JobObserver {
  @override
  void onStart(Job<Object?> job) => print('$job started');

  @override
  void onFinish(Job<Object?> job) => print('$job: ${job.outcome}');

  @override
  void onError(Job<Object?> job, Object error, StackTrace stackTrace) =>
      print('$job: $error');

  @override
  void onLog(Job<Object?> job, String message) => print('$job: $message');
}
```

У ошибок два пути, и это не одно и то же. Ошибка тела идёт наблюдателю и
становится исходом `Failed`; в зону она попадает, только если исход никто
не наблюдал. Три ошибки, которым больше некуда идти, — поздний отказ
действия, брошенного `wait`, ошибка диспозера и ошибка колбэка `onCancel` —
идут наблюдателю, а без него сразу в зону. Тишина — выбор того, кто
слушает.

## Отложенный старт

`Job.deferred(body)` возвращает `DeferredJob<T>` — с добавкой в виде
публичного `start()`. Запускает задачу тот, кто ею распоряжается: вручную,
очередь или родитель через `ctx.run(child)`.

```dart
final job = Job.deferred<void>((ctx) => ctx.wait(work));
// ... позже, или из своей очереди
job.start();
```

## Своё поверх ядра

`JobBase<T>` и `JobContextBase` — два класса, которые наследует движок
предметной области. Наследник добавляет то, чего у ядра нет, — состояние,
очередь, правила, — и всё, что нужно движку, объявлено защищённым: статус,
отмеченная отмена, дети, старт, завершение, отмена с флагом отклоняемости и
два хука, которые задача предметной области заполняет сама, — `started()` и
`finished()`.

```dart
final class MyJob<T> extends JobBase<T> {
  final Future<T> Function(MyContext ctx) _body;

  MyJob(this._body, {super.key, super.observer});

  @override
  JobContextBase createContext() => MyContext(this);

  @override
  Future<T> execute(covariant MyContext ctx) => _body(ctx);
}

final class MyContext extends JobContextBase {
  MyContext(super.owner);
}
```

Две вещи стоит знать заранее. `check()` — контрольная точка, через которую
проходит каждый член семьи ожидания: `wait`, `join` и `uncancellable`
начинают с неё, — поэтому область, которая проверяет больше отмены,
переопределяет её и получает всю семью бесплатно. И `@protected` действует
только внутри наследника: движку, который трогает задачу со стороны, нужны
приватные обёртки на своём наследнике, а не прямые вызовы.

`solo` устроен именно так и реэкспортирует этот пакет целиком.

## solo

[solo](https://pub.dev/packages/solo) добавляет поверх этих задач
состояние, очередь и правила: не больше одной корневой задачи в момент,
монопольное владение состоянием, декларативные правила. Если нужен
контроллер, а не задача, начинайте оттуда.
